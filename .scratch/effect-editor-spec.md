## Problem Statement

用户打开「灯效编辑」时根本不知道从哪里下手。

现在的灯效能力被拆成了三个互不相通的地方：

- **设备控制页**：能选段、拖动色环、点颜色预设——但只能改颜色，改不了灯效类型、区间、图层。
- **段编辑页**：能选类型、填区间、配两层、选叠加方式——但只能手动输入起止数字，没有选择器；而且必须点「应用」才生效，离开页面草稿就丢。
- **剧本页**：能编多阶段时间轴——但**必须先在设备控制页选中一个段**，才能把段加进阶段。用户无法从剧本页独立创作，页面上的提示「先在设备控制页选一个段」对一个新手来说等于死路。

叠加的问题：

- 术语是工程语言：「段」「第 1 层 / 第 2 层」「混合方式」「blend」「下发」「激活」。
- 段从 0 编号（「段 0」）而阶段从 1 编号（「阶段 1」），混用。
- 剧本页脚注写着「段参数在『灯光 / 段编辑』页设置」，但**「灯光页」根本不存在**（早已并入设备页）。
- 「下发剧本」实际上还会激活，按钮说的和做的不一致。

结果是：用户能点开这些页面，但看不懂，也不知道下一步该做什么。

## Solution

把灯效编辑收敛成**一个页面、两档能力**，用顶部的分段开关切换：

**快捷**（默认）——用户点的是结果，不是规格。
横排成品效果卡：暖白常亮 / 呼吸 / 彩虹流动 / 流光追逐 / 冷蓝氛围 / 紫色氛围。点一下，整组灯珠立刻变成该效果。卡片下方只暴露少数人话档位（颜色、快慢慢/中/快、最暗微亮/中暗/全暗、尾长短/中/长、顺向/逆向、彩虹饱和度）。没有毫秒，没有 0–255。

**自定义**——完整编排能力，一棵三级树：
```
灯效方案（1-4 个槽位）
  └─ 步骤 1…8              ← 每个步骤 = 一个时间段
       └─ 光区 1…8          ← 该时间段内把灯组切成多段
            └─ 主效果 + 叠加效果 + 叠加方式
```

编辑某个步骤时，它的光区会实时写进设备作为**预览**；点「写入灯控」才把整套方案提交（并启用）。协议要求整套提交，所以预览借用实时灯效通道。

两档之间切换时，**自定义档的编排会以内存快照保留**，切回来自动恢复并轻提示「已恢复你之前的编排」。

同时收窄设备控制页：移除段列表、色环、颜色预设，只留电源、亮度、各灯组开关，加一行「当前灯效」摘要（点它进对应编辑）。

## User Stories

1. 作为模玩玩家，我想打开灯效页就看到几个成品效果卡，这样我不用理解灯效类型和参数也能让模型亮起来。
2. 作为模玩玩家，我想点一下「呼吸」就让整组灯珠开始呼吸，这样最小操作就能看到效果。
3. 作为模玩玩家，我想在快捷档里更换颜色，这样同一套效果能适配不同模型涂装。
4. 作为模玩玩家，我想调整呼吸的最暗程度，这样暗处不会完全熄灭、能保留一点存在感。
5. 作为模玩玩家，我想调整快慢（慢/中/快），这样不同场景可以用不同节奏。
6. 作为模玩玩家，我想给彩虹加饱和度控制，这样它能从「鲜艳彩虹」调到「柔和光带」。
7. 作为模玩玩家，我想给流光选尾长，这样从硬边亮点到长拖尾都在我控制范围内。
8. 作为模玩玩家，我想选流光/彩虹的方向，这样它能顺着模型结构走。
9. 作为模玩玩家，我想在多灯组设备上先选灯组，这样只改我要改的那一组。
10. 作为模玩玩家，我想看到当前选中的效果卡有明确高亮，这样我知道自己现在是什么状态。
11. 作为模玩玩家，我想在快捷档里调整参数后立即看到灯变化，这样我不用反复「应用」试探。
12. 作为模玩玩家，我想切到自定义档编排复杂效果，这样模型不同部位可以有不同的灯效。
13. 作为模玩玩家，我想在自定义档里把灯组切成多个光区，这样前半段和后半段可以两种效果。
14. 作为模玩玩家，我想在灯珠条上直接拖选区间，这样不用自己数灯珠编号。
15. 作为模玩玩家，我想用「整条 / 前半 / 后半 / 平均切分」快速划出光区，这样第一次编辑不用从零开始。
16. 作为模玩玩家，我想看到光区重叠立刻变红并被拦住，这样我不会发出一个必定被设备拒绝的配置。
17. 作为模玩玩家，我想给一个光区叠加第二层效果，这样能得到「彩虹×呼吸」这类复合效果。
18. 作为模玩玩家，我想选叠加方式（覆盖/相乘/相加），这样第二层的混合行为符合预期。
19. 作为模玩玩家，我想在自定义档里编多个步骤组成灯效方案，这样模型能随时间变化。
20. 作为模玩玩家，我想调整每个步骤的时长，这样每个阶段停留多久由我决定。
21. 作为模玩玩家，我想调整步骤顺序，这样我能快速改播放次序。
22. 作为模玩玩家，我想在编辑某个步骤时实时预览它的光区，这样我不用整套写完才知道效果。
23. 作为模玩玩家，我想在预览前有明确提示「预览会停止正在播放的方案」，这样我不会以为播放坏了。
24. 作为模玩玩家，我想把方案写入灯控并启用，这样拔掉手机后模型还能自己演。
25. 作为模玩玩家，我想在 1-4 个方案槽位之间切换，这样我可以准备多套场景（白天/夜间/展示）。
26. 作为模玩玩家，我想在自定义档看到方案、步骤、光区三级的当前位置，这样我知道自己在编辑树的哪一层。
27. 作为模玩玩家，我想从自定义档切回快捷档时保留我的编排，这样手滑切回去不会丢东西。
28. 作为模玩玩家，我想切回自定义档时自动恢复之前的编排，这样我不必重新搭一遍。
29. 作为模玩玩家，我想在切换后看到「已恢复你之前的编排」的提示，这样我知道配置没丢。
30. 作为模玩玩家，我想在设备控制页看到一行「现在亮的是什么」，这样我打开就能确认状态。
31. 作为模玩玩家，我想从那一行摘要直接点进对应编辑，这样不用自己找入口。
32. 作为模玩玩家，我想设备控制页只保留开关与亮度，这样不会被三处不同的编辑入口搞混。
33. 作为模玩玩家，我想界面里不出现「blend」「毫秒」「0-255」这些词，这样我不用懂协议。
34. 作为模玩玩家，我想编号统一从 1 开始，这样「光区 1」就是第一个而不是第零个。
35. 作为模玩玩家，我想看到一个不存在的页面名字时不会困惑，这样界面说的是真的。
36. 作为模玩玩家，我想写入失败时界面显示设备的真实状态，这样我不会对着一个假的成功状态继续调。
37. 作为模玩玩家，我想写入失败时看到具体原因（比如与某个光区重叠），这样我知道该改哪里。
38. 作为模玩玩家，我想删除光区时二次确认，这样不会误删已经调好的配置。
39. 作为模玩玩家，我想在浅色和深色主题下都能看清所有卡片与文字，这样白天黑夜都能用。
40. 作为模玩玩家，我想在设备未连接时正确看到提示与禁用态，这样我不会对着灰色控件反复点。

## Implementation Decisions

### 页面结构

- **底部 tabBar 改为两项：设备 / 发现**。「剧本」tab 删除。
- 设备详情页（从首页大卡进入）顶部加分段开关：**快捷 / 自定义**。两种模式共用同一个页面与同一份已连接会话。
- **删除 `pages/segment-edit`**：它被自定义档完全吸收。路由表与相关测试同步清理。
- 设备详情页收窄为：电源、亮度、各灯组开关、一行「当前灯效」摘要（点击进入对应模式）。段列表、色环、颜色预设移除。

### 快捷档

- 6 张成品卡：暖白常亮、呼吸、彩虹流动、流光追逐、冷蓝氛围、紫色氛围。前 4 张对应协议四种灯效，后 2 张是同效果换色。
- 快捷档作用于**当前选中灯组的整条**（`0 .. ledCount-1`），槽位固定 0，单层，叠加方式覆盖。
- 参数以三档人话暴露（慢/中/快、微亮/中暗/全暗、短/中/长、顺向/逆向），内部映射到协议值；彩虹额外有饱和度滑杆（0–100%，映射到 `sat` 0–255）。
- 改动即时生效：300ms 防抖后直接 `SetSegment`，没有「应用」按钮。
- 若检测到方案正在播放，先 `SetPlayback(stop)` 并提示「已停止方案，改为实时灯效」——因为固件在方案播放期间会忽略实时灯效区。

### 自定义档

- 三级树：**灯效方案（4 槽）→ 步骤（最多 8）× → 光区（每灯组最多 8）→ 主效果 + 叠加效果 + 叠加方式**。
- 光区编辑：灯珠条拖动划选 + 快捷切分按钮（整条 / 前半 / 后半 / 平均 2–4 段）+ 数字精修入口。
- 光区重叠在本地预检拦截，一帧不发；重叠区域在灯珠条上标红。
- 主效果与叠加效果各自可选四种灯效；叠加效果为空时叠加方式强制为「覆盖」（协议要求）。
- 编辑某步骤时，其光区实时写入设备作为预览；「写入灯控」提交整套方案（Begin → 各步骤 → Commit → Activate，但**不自动播放**）。
- 术语：方案 / 步骤 / 光区 / 主效果 / 叠加效果 / 叠加方式 / 写入灯控 / 启用这套方案。
- 编号统一从 1 开始显示。

### 模式切换与快照

- 自定义档的编排（方案、步骤、光区、图层）在切到快捷档时以**内存快照**保留，不落存储。
- 切回自定义档自动恢复，并轻提示「已恢复你之前的编排」。
- 快照作用域为当前设备 + 当前灯组；换设备或换灯组不串号。

### 术语重写（用户可见文案；代码标识不动）

| 现在 | 改成 |
|---|---|
| 设备 | 灯控 |
| 灯带 N | 灯组 N |
| 段（段 0） | 光区（从 1 编号） |
| 第 1 层 / 第 2 层 | 主效果 / 叠加效果 |
| 混合方式 / blend | 叠加方式 |
| 阶段（阶段 1） | 步骤（步骤 1） |
| 剧本 | 灯效方案 |
| 下发剧本 | 写入灯控 |
| 激活剧本 | 启用这套方案 |
| 简单模式 | 快捷 |
| 高级模式 | 自定义 |

代码内部的 `segId` / `layer0` / `stripId` / `scriptId` 等标识保持不变，避免牵连字节契约与既有测试。

### 协议约束（不可绕过，UI 必须体现）

- 只有四种灯效类型 + 空层；只有三种叠加方式；最多两层。
- 每个灯组最多 8 个光区，最多 8 个灯组，每灯组 1–64 灯珠。
- 每套方案最多 8 个步骤，最多 4 套方案；步骤时长 1–65535ms。
- **步骤里的光区是快照副本**，改实时光区不影响已存在的步骤。
- **方案内容无法从灯控读回**，只有 4 字节摘要（阶段数 / 是否启用 / 循环位）。因此本地草稿是唯一记录，界面必须如实说明这一点。
- 4 套方案共享 16KB 持久化预算，超限在写入前拦截。

### 写入失败的处理

- 即时写入失败：重新 `queryStrip` 读回设备真实值并刷新界面（用户改动不保留），同时提示具体原因。
- 本地预检失败（区间非法、重叠、参数越界）：一帧不发，就地提示。

## Testing Decisions

好的测试只验证**外部可观察行为**，不断言内部实现细节。本项目的既有测试就是这个风格：纯函数模块用表驱动断言输入输出，页面层用契约测试锁住「不会崩」的结构性约束，真机/模拟器用自动化脚本验证可点击性与状态流转。

沿用现有接缝，不新开页面级测试：

- **`quick-effects`（新增纯函数模块）**：卡片到协议层的映射、六个档位到协议值的对应、整组 spec 的区间与槽位、参数摘要文案。测试文件 `tests/quick-effects.test.ts`。参照 `tests/segment-editor.test.ts` 的写法（直接构造输入、断言输出形状与边界）。
- **`effect-layout`（新增纯函数模块）**：光区不重叠校验、默认切分（整条/前半/后半/均分）产出的区间、逐灯珠覆盖与冲突标记。测试文件 `tests/effect-layout.test.ts`。参照 `tests/segment-editor.test.ts` 中 `buildLedCells` / `findOverlap` 的用例风格。
- **`effect-mode`（新增纯函数模块）**：快捷/自定义模式的快照与恢复——按设备与灯组隔离、切换往返一致、无快照时的兜底。测试文件 `tests/effect-mode.test.ts`。这是最关键的一处：所有「切模式丢配置」的缺陷都会在这里暴露。
- **`script-view`（现有模块）**：方案/步骤的增删改、时长解析、容量估算。复用 `tests/script-view.test.ts` 与 `tests/script-capacity.test.ts`，按新术语调整断言文案。
- **配置与绑定契约**：`tests/app-config.test.ts` 已锁住「页面四件套齐全」「tabBar 页面已注册」「WXML 绑定在 TS 里存在」。删除 `segment-edit` 与剧本 tab 后，这些断言会自动覆盖新结构。
- **端到端**：`.auto/verify-redesign.mjs` 与 `.auto/verify-deep.mjs` 已有 28 + 27 项。改造后需更新为：点快捷卡后设备状态真的变、切自定义再切回能恢复、写入失败会回滚。`tests/mock-session.test.ts` 提供会话级链路验证（不经过页面）。
- **双主题**：`tests/theme.test.ts` 已锁住浅/深两套变量的对比方向与「页面 wxss 不散落硬编码色」。新增面板必须遵守，否则该测试会红。

## Out of Scope

- 修改协议字节布局或固件行为（本轮纯小程序侧）。
- 让用户上传/导入灯效方案文件。
- 方案内容的跨设备云同步（后端目前没有这个能力）。
- 快捷档「一键同步到全部灯组」。
- 方案之间的过渡（fade）——协议里 `fade_ms` 是预留位，固件恒为 0。
- 温度/电流保护相关的灯效降级。
- 快捷档卡的动效预览（卡片只显示静态色块与标题）。

## Further Notes

- **快捷档的实时写入依赖一个协议事实**：`SetSegment` 是绝对值命令，重复下发只覆盖自己，因此防抖重发是安全的。这一点与 #48 的「改色必须基于读回的完整 spec」是同一类保障——不能凭空构造 spec 覆盖已有段。
- **方案播放期间实时光区不可见**：固件按 `active_segments` 渲染，实时光区仍写进 `s_segments` 但不参与出光。快捷档因此必须主动停止方案，否则用户点了效果却看不到变化。这是「操作必须有可见反馈」的硬要求。
- **快照只在内存**：不落存储，避免「上次的编排无限期占着存储」与「恢复出的配置与设备当前状态不一致」两个新问题。刷新小程序后回到设备真实状态是符合预期的。
- **术语替换只动用户可见文案**：代码标识不动，避免牵连字节契约与既有测试；`tests/theme.test.ts` 的「无硬编码色」规则同样适用于新增面板。
