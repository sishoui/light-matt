## Parent

#52 小程序：灯效编辑重构（快捷 / 自定义两档 + 术语重写）

## What to build

把「光區」这个概念在代码里收敛到一处，为后面四张票扫清障碍。这是一个**纯重构**：不改任何界面、不改任何设备行为，现有测试全绿。

具体做三件事：

1. 现有 `segment-editor` 里仍要用的能力（默认区间、区间解析、逐灯珠视图、层校验）与新写的 `effect-layout`（区间校验 / 重叠 / 切分）职责重叠，需要明确「谁负责什么」：区间与布局归 `effect-layout`，灯效参数校验归 `segment-editor`，两者不互相依赖。
2. 把「一个光区」的完整形状（区间 + 主效果 + 叠加效果 + 叠加方式）定义成一个可复用的构造与读取入口，让快捷档和自定义档都能用它，而不必各自拼 21 字节载荷。
3. 为删除 `segment-edit` 页做好准备：把该页里唯一独有、且新界面还要用的逻辑（两层折叠态、预设匹配）下沉到纯函数模块，页面本身只留展示。

验收时旧页面仍然可用，行为与现在完全一致。

## Acceptance criteria

- [ ] 区间校验与重叠判定只在 `effect-layout` 里实现一份，`segment-editor` 不再重复实现
- [ ] 现有 `segment-editor` 相关测试全部仍然通过，断言语义未变
- [ ] 新增或调整的纯函数有对应单测（表驱动，参照 `effect-layout` 的既有写法）
- [ ] `tsc --noEmit` 干净，`vitest run` 全绿
- [ ] 界面上看不到任何变化
