## Parent

#52 小程序：灯效编辑重构（快捷 / 自定义两档 + 术语重写）

## What to build

用户能把「多个步骤」串成一套**灯效方案**，并让模型自己随时间演。

结构是一棵三级树，用户始终能看清自己在哪一层：

```
灯效方案（1–4 号槽位）
  └─ 步骤 1…8            ← 每个步骤是一个时间段
       └─ 光区 1…8        ← 该时间段内灯组怎么分段
            └─ 主效果 + 叠加效果 + 叠加方式
```

具体能力：

- 在 4 个方案槽位之间切换，各自独立编辑，互不覆盖。
- 增删步骤、调整步骤顺序、改每个步骤的时长。步骤数量上限 8，至少保留 1 个。
- 每个步骤内部复用上一票的多光区编辑器，并且**每个光区还能叠加第二层效果**（主效果 + 叠加效果），可选叠加方式：覆盖 / 相乘 / 相加。叠加效果为空时叠加方式固定为覆盖（协议要求，UI 需禁用并说明）。
- 编辑某个步骤时，它的光区实时写进设备作为**预览**；预览前若方案正在播放，先停止并提示。
- 点「写入灯控」把整套方案提交到设备并启用（但不自动播放）；点「播放」才真正跑时间轴。
- 4 套方案共享 16KB 持久化预算，超限在写入前拦截并说明。
- 设备上的方案内容**无法读回**，只有摘要（步骤数 / 是否启用 / 是否循环）。界面必须如实说明这一点，不能让用户以为可以「拉回来改」。

## Acceptance criteria

- [ ] 4 个方案槽位可切换，编辑 A 不影响 B
- [ ] 可增删步骤、可调顺序、可改时长；达到 8 个上限有提示
- [ ] 每个步骤内可建多个光区，每个光区有主效果 + 可选叠加效果
- [ ] 叠加效果启用时可选覆盖 / 相乘 / 相加；未启用时该控件禁用并说明原因
- [ ] 编辑步骤时该步骤的光区会实时写到设备（能看到灯变）
- [ ] 写入前若方案在播放，会自动停止并提示
- [ ] 「写入灯控」成功后设备摘要显示该方案已提交且已启用
- [ ] 「播放」让时间轴跑起来，暂停/停止行为正确
- [ ] 超容量时禁止写入并给出可读原因
- [ ] 界面明确告知「方案内容不能从设备读回」
- [ ] 未连接时整块禁用并给出提示
- [ ] 步骤/方案数据模型纯函数有单测；`tsc` 与 `vitest` 全绿；双主题可读
