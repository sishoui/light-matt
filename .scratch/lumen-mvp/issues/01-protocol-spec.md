# 01：协议定稿与跨端测试向量

> 已定稿并关闭：GitHub #2。字节级契约见 `docs/protocol.md`，测试向量见 `docs/protocol-testvectors.json`。

**要构建什么**：一份让固件和小程序各自关起门来实现、最后能一次对上的字节级协议契约，以及两端共用的可执行测试向量。

契约必须覆盖：命令字表（设开关、设亮度、设颜色、一次设全部、查询状态、设灯珠数量、自检）、每个命令的载荷布局与逐字段字节核算、校验和算法与覆盖范围、结果码枚举、seq 语义、State 特征值布局、Service/Characteristic UUID，以及边界语义（亮度/颜色越界、未知命令、坏 magic / 坏 length / 坏校验、ACK 在状态生效前还是后、version 处理、NVS 写失败回什么）。

**阻塞于**：无（可立刻开始）

**状态**：ready-for-agent

- [ ] 每个命令的载荷实际字节数核算过，全部 ≤ 14 字节；超预算的命令已砍掉或改结构，没有引入分包
- [ ] 每个字段的偏移、宽度、字节序、取值范围逐条写明
- [ ] 校验和算法有可执行伪代码，并给出一个人工能验算的例子
- [ ] 结果码覆盖成功、参数越界、未知命令、校验失败、忙/暂不可用
- [ ] State 的 read 布局与「查询状态」的应答载荷完全一致
- [ ] 边界语义逐条写死，不留「看实现」
- [ ] 测试向量覆盖：开灯、关灯、设亮度、设颜色、一次设全部、查询状态、设灯珠数量、自检、合法帧、坏校验、坏 magic、超长、未知命令、边界值（0 / 255 / 灯珠数上限）
- [ ] 另一个实现者只读契约就能写出 codec，不需要再问任何问题

> 本票与 wayfinder 地图的【协议规格定稿】是同一份交付，执行一次即可，不要两边各做一遍。
