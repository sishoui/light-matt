# 04：小程序 BLE 平台能力探针

**要构建什么**：一个最小可跑的小程序页面，只做「扫描 → 连接 → 协商 MTU → 订阅 notify → 写一帧 → 收到回显」，用最小 GATT 服务验证平台能力，不包含任何业务逻辑与协议解析。

目的是把小程序侧的平台差异在业务代码进来之前摸清楚：Android/iOS 的 deviceId 形态、`setBLEMTU` 的实际效果与 iOS 跳过策略、`writeNoResponse` 的连续发送安全间隔、notify 订阅与断线的行为、定位权限与蓝牙开关的异常表现。

**阻塞于**：02（微信开发者工具要能真机预览）

**状态**：ready-for-agent

- [ ] Android 真机能扫到并连上，MTU 协商结果记录在案
- [ ] iOS 真机能扫到并连上，deviceId 形态记录在案
- [ ] 发出一帧，设备回显被 notify 收到
- [ ] 断线 → 重连流程走通一次
- [ ] `writeNoResponse` 连续发送的安全间隔有推荐值
- [ ] 记录国产 Android 机型的权限/蓝牙开关异常行为（若有）
