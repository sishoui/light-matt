# 05：固件 GATT 骨架

**要构建什么**：固件的分层骨架：`ble_link`（GATT + 帧收发）、`led_engine`（共享状态 + 渲染任务）、`state_store`（NVS）。这一票只钉边界，不实现完整命令语义。

要钉死三件事：BLE 回调里允许做什么/禁止做什么；latest-wins 邮箱的具体机制（互斥锁 + dirty 标志 + 二值信号量）；NimBLE 的 GATT 定义方式与三个特征值的属性。同时确定单连接配置、NimBLE 主机任务与渲染任务的优先级和栈大小，并记录理由。

**阻塞于**：01（UUID、State 布局与帧格式要先定）、03（渲染任务复用点灯验证的调用方式）

**状态**：ready-for-agent

- [ ] 编译通过，烧录后串口正常运行
- [ ] nRF Connect 能看到 Service 与 RX / TX / State 三个特征值，属性正确
- [ ] 写入 RX 触发串口打印「收到 N 字节」，但灯带不变（骨架验证）
- [ ] 渲染任务空闲时不空转
- [ ] 设备只接受 1 个连接，旧连接释放后能重新连上
- [ ] 三个模块的公开接口清晰，跨层调用只有一个方向
- [ ] 任务优先级与栈大小有记录，符合 C3 单核约束
