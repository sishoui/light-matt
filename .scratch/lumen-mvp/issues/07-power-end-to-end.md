# 07：开关端到端（walking skeleton）

**要构建什么**：第一条真正打通手机的纵向路径。真机扫到设备 → 连上 → 按开关 → 灯带亮/灭 → 收到 ACK。这一票故意是最大的一刀，因为它要建立后续所有切片共用的 walking skeleton：固件侧的帧解码与命令分发、小程序的传输层与 codec、单页面的连接状态条与开关按钮。

范围只含「设开关」这一条命令。亮度、颜色、状态同步、持久化都留给后续票。但骨架必须一次建对：写入串行化、20Hz 节流位置、错误码分诊、协议日志缓冲的接口都在这一票定下来。

**阻塞于**：01（协议与测试向量）、02（环境）、03（灯带能亮）、04（平台差异已摸清）、05（GATT 骨架）

**状态**：ready-for-agent

- [ ] 真机（Android 或 iOS 至少一台）扫到并连上
- [ ] 点击开关，灯带在可感延迟内亮/灭
- [ ] 每次操作在小程序 console 看到完整 hex，在固件串口看到 cmd / seq / 结果码
- [ ] ACK 的 seq 与请求一致
- [ ] 坏校验帧不改变灯带且回对应结果码
- [ ] 超长帧被拒绝，不截断执行
- [ ] 两端 codec 测试跑同一份向量并通过
- [ ] 写操作串行化，不出现并行写失败
- [ ] 单页面布局为后续控件留好位置，不需要重排

> 这是 spec 里「开关 + ACK」的最小可演示路径。后续每一票只增加一条命令或一层行为，不重建骨架。
