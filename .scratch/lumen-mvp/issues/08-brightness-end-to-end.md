# 08：亮度端到端

**要构建什么**：一条完整的亮度路径。拖动滑块 → 节流层 → BLE 写入 → 固件解码 → 状态更新 → gamma + 亮度乘算 → 灯带实时跟随。同时落实开关与亮度解耦的语义。

这一票要把「跟手」做成可验证的行为：20Hz 上限、latest-wins（新值覆盖未发出的旧值）、连续量不重传、亮度 0 等价关灯、关灯保留亮度。固件的 gamma 与亮度乘算在这一票定型，后续颜色命令直接复用。

**阻塞于**：07（walking skeleton 已打通）

**状态**：ready-for-agent

- [ ] 拖动滑块灯带实时跟随，无可感延迟
- [ ] 100Hz 输入 → 输出不超过 20Hz，且发的是最新值（单测）
- [ ] 关灯再开恢复原亮度
- [ ] 亮度拖到 0 等价关灯
- [ ] 低亮度平滑，无明显跳变或闪烁
- [ ] 亮度越界按协议规定处理（钳位或拒绝），两端行为一致
- [ ] 连续调光不重传旧值，松手后不回跳

> 亮度乘算必须建立在协议规定的颜色模型上；gamma 只在固件，不在小程序。
