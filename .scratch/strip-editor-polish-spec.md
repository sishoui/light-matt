## Problem Statement

进阶档编辑器（当前在 `integration/ui-refactor-v4` 的 `pages/strip`）已经能编排「方案 → 步骤 → 光区 → 效果」，但用户拿起来用时有六个明确的不满：

**灯珠数量不可控，也看不全。** 每条灯组实际接多少颗灯珠，只能退到设备信息页、一次选一条灯组、手打一个数字再点应用；编辑器里完全看不到、也改不了。上限 64 颗对「每个引脚接不同长度的灯带」这个真实场景太紧——一条 100 颗的灯带根本无法配置。

**时间轴会跑出屏幕。** 八个步骤一起排时总宽 376px，超过多数手机的可用宽度，于是变成横向滚动；步骤越多、时长越碎，越要左右划着看，失去了「一眼看到整段节奏」的意义。

**拖拽没有反馈。** 长按进入拖动后，被拖的块只是变半透明，不跟手；目标块描一圈蓝边。用户的手指在动，画面却不跟着动，松手前完全不知道会落到哪里。

**光区的起止看不出来。** 选中光区只在块内侧描一圈边，而「这段从第几颗到第几颗」「起点在哪一端」没有独立标记。灯珠弹窗里也只有整片格子，起点只是一个淡色小圆点，确认前无法用数字核对。

**方案槽位是四个永远占着的坑。** 顶部一个按钮在 ①–④ 之间轮换，四个槽位一直在，空槽标「空白」，不能新建也不能删除。更严重的是：方案草稿按「设备 + 灯组 + 槽位」存，而写入时直接把槽位号当成设备的 `script_id`——**灯组 1 的方案① 和灯组 2 的方案① 写的是设备上同一个 `script_id`**，后写的会覆盖前一个，另一条灯组在那套方案里变成全暗。

**灯效只有四种，且没有「什么都不显示」。** 静态 / 呼吸 / 彩虹 / 流光之外没有更多选择；想在编排里让某一段熄灭，只能靠「不画光区」，而空着的光区在时间轴上没有任何显式表达。爆闪与心跳这两个最常用的演出效果做不出来。

## Solution

### 灯珠数量

- 设备信息页把「灯珠数量」从「选灯组 → 输入框 → 应用」改成**每组一条 1–100 的滑块**，拖动松手即下发；页面顶部显示**总灯珠数**（各灯组合计的只读数字）。
- 灯组详情页顶部也放一条当前灯组的灯珠数滑块，改完就地生效，不用退两层页面。
- 协议上限从 64 抬到 100。`start` / `end` 本来就是 1 字节，**线上字节布局不变**，涨的只有固件侧缓冲与校验常量。

### 时间轴：固定宽度、不滚动

- 总宽恒等于容器宽度，**彻底删掉横向滚动**。
- 块宽按步骤时长比例分配，每块有 **24px 下限**；下限放不下时先把块间隙从 8px 压到 4px，还不够就退化为均分——任何分布下都不出容器、都点得中。
- 块宽不足 48px 时不画时长文字，只留序号；时长看下方数值行。

### 拖拽：抬起、跟手、邻块让位

- 长按 300ms 后块抬起：放大 1.06、加投影、跟随手指横向移动。
- 原位置到落点之间的块整体平移一个块宽，让出插槽，150ms 过渡；落点块高亮描边。
- 松手提交顺序并回弹。全部用 `transform` 实现，不改 `flex`（小程序里 flex 重排动画不稳）。

### 光区：起止节点显式化

- 光区轴上选中块加 2px 主题色描边，**两端各画一个高于条带的圆形手柄**；轴下方显示「第 0–19 颗 · 20 颗」。
- 灯珠弹窗里起点画**实心圆点 + 加粗数字**，终点画**空心圆环**，区间内格子填半透明主题色。
- 弹窗底部加两个**数字滚轮**（起点 / 终点）。滚轮的值域只包含与当前锚点连通的**那一段连续空闲灯珠**——被别的光区占着的序号根本不出现在滚轮里。显示按 1 基，内部仍 0 基。

### 方案：设备级、动态槽位

- 方案改为**设备级**：4 个固定 `script_id`，每套覆盖所有灯组；灯组页只编辑当前灯组在这套方案里的那一片。
- 进入页面**只显示一个槽**；「+ 新建方案」占用下一个未使用的 `script_id`，最多到 4 个（全满时按钮禁用）。
- 每套方案可删除，**删除后不重排编号**（删掉②就剩 ①③④），避免设备上的 `script_id` 整体搬家。
- 删除同时清设备：新增一条 `0x1E ClearScript` 命令真正清掉该 id 的已提交内容。

### 灯效：三种新类型

- 新增 **爆闪**、**心跳**、**熄灭** 三种类型；参数块沿用现有 7 字节形状，**层编码宽度不变、协议版本号不变、帧长不变**。
- 进阶档效果类型行从 4 个变 7 个；简单档成品卡从 6 张扩到 **9 张**（原有 6 张 + 爆闪白 / 心跳暖红 / 熄灭黑），三列网格。
- 叠加层可选爆闪与心跳，**不给熄灭**（叠加熄灭等于没做事）。

## User Stories

### 灯珠数量

1. 作为灯带用户，我想在设备信息页用一条滑块设置每条灯组的灯珠数，这样我不用反复打数字再点应用。
2. 作为灯带用户，我想一次看到这台设备的总灯珠数，这样我不用自己把几条灯组加一遍。
3. 作为灯带用户，我想把某条灯组设成 100 颗，这样我能接一条比原来更长的灯带。
4. 作为灯带用户，我想在灯组详情页直接调当前组的灯珠数，这样我发现实际长度不对时不用退两层页面。
5. 作为灯带用户，我想滑块范围是 1–100 而不是 0–100，这样我不会把一条灯组设成不存在的长度。
6. 作为灯带用户，我想拖动滑块时不逐帧下发、松手才生效，这样设备不会被连续命令刷屏。
7. 作为灯带用户，我把灯珠数改小、已有光区越界时，我想先看到「有 n 个光区超出新长度」的确认，这样我不会莫名其妙丢编排。
8. 作为灯带用户，我想在确认后越界光区被截到新末尾、完全越界的被删掉，这样编排仍然可用。
9. 作为灯带用户，我想取消改动时设备与草稿都不变，这样我误拖滑块不会付出代价。
10. 作为灯带用户，我想同一台设备上两条灯组可以是不同长度（例如 100 和 24），这样多灯组不是必须等长。

### 时间轴

11. 作为灯带用户，我想时间轴总是完整铺满一屏，这样我不用左右划着看步骤。
12. 作为灯带用户，我想八个步骤一起排时每个都还能点中，这样极短步骤不会变成一条点不中的线。
13. 作为灯带用户，我想极短步骤的宽度不低于一个能看清的下限，这样我知道它在那里。
14. 作为灯带用户，我想块太窄时不显示时长文字，这样文字不会溢出到邻块上。
15. 作为灯带用户，我想点时间轴的任一块切换当前步骤，这样下方的时长与光区跟着切换。
16. 作为灯带用户，我想看到每一步的序号，这样窄块也知道是第几步。

### 拖拽

17. 作为灯带用户，我想长按后块抬起来并跟着我的手指走，这样我知道自己在拖哪一块。
18. 作为灯带用户，我想拖动时其它块给它让出插槽，这样我能预览落点。
19. 作为灯带用户，我想落点块高亮，这样松手前我确认会插到哪。
20. 作为灯带用户，我想松手后顺序真的改变且当前选中步骤跟着走，这样我不会拖完发现选中的还是老步骤。
21. 作为灯带用户，我想拖拽结束后不会误触发一次点击，这样顺序不会因为手指抬起而跳一下。

### 光区轴与灯珠弹窗

22. 作为灯带用户，我想选中光区时两端各有一个明显的手柄，这样我一眼看出这段从哪到哪。
23. 作为灯带用户，我想选中光区时轴下方显示「第 x–y 颗 · n 颗」，这样我能用数字核对。
24. 作为灯带用户，我想弹窗里起点是实心点、终点是空心环，这样我能分清哪端是起点。
25. 作为灯带用户，我想弹窗里区间内格子有底色，这样我确认选中的范围。
26. 作为灯带用户，我想用两个数字滚轮直接选起点和终点，这样我不用在几十个格子里数。
27. 作为灯带用户，我想滚轮里不出现已被别的光区占用的序号，这样我不可能选出非法区间。
28. 作为灯带用户，我想滚轮只给出与起点连通的那一段连续空闲，这样我选出来的区间永远合法。
29. 作为灯带用户，我想任一端一改网格立刻预览，这样我不用反复确认。
30. 作为灯带用户，我想区间无效时确定按钮是灰的，这样我不会提交一个被设备拒绝的配置。
31. 作为灯带用户，我想被占用的格子置灰且点不动，这样我不会画出重叠。
32. 作为灯带用户，我想点同一颗两次视为取消，这样不会产生只含一颗灯珠的光区。

### 方案

33. 作为灯带用户，我想进来只看到一个方案，这样我不会被四个空坑搞糊涂。
34. 作为灯带用户，我想点「+ 新建方案」占用下一个空位，这样我能按需要增加而不是一开始就有四个。
35. 作为灯带用户，我想最多有四个方案，这样界面不会超出设备能力。
36. 作为灯带用户，我想四个方案都在用时新建按钮禁用，这样我不会点了没反应。
37. 作为灯带用户，我想删除一套方案并真的从设备上清掉，这样「删除」不是半成品。
38. 作为灯带用户，我想删除后编号不重排，这样设备上其它方案不会跟着搬家。
39. 作为灯带用户，我想每套方案 tab 上看到「空白」或「n 步」，这样我知道哪套有内容。
40. 作为灯带用户，我想在灯组 A 编辑方案① 时不会把灯组 B 在方案① 里的内容清掉，这样多灯组设备上我不怕串档。
41. 作为灯带用户，我想灯组页显示的方案指的是这台设备的方案，这样我不会以为每条灯组能各存四套。

### 灯效

42. 作为灯带用户，我想有爆闪效果，这样我能做出生硬的频闪感。
43. 作为灯带用户，我想爆闪能调频率与占空比，这样窄闪和宽闪都能做。
44. 作为灯带用户，我想有心跳效果，这样我能做出双脉冲的呼吸感。
45. 作为灯带用户，我想心跳能调节奏（BPM），这样我能让它跟音乐的快慢。
46. 作为灯带用户，我想有熄灭效果，这样我能在编排里让某一段黑掉。
47. 作为灯带用户，我想在简单档点一张卡就得到这些新效果，这样我不用进进阶档。
48. 作为灯带用户，我想简单档的卡从 6 张变成 9 张且排成三列，这样一屏仍然放得下。
49. 作为灯带用户，我想把爆闪或心跳当叠加层用，这样我能在底色上再加闪光。
50. 作为灯带用户，我想叠加层里没有「熄灭」，这样我不会选到一个等于没做事的效果。
51. 作为灯带用户，我想新效果与老效果在界面上用同一套参数控件，这样我不用重新学一遍。

### 兼容与诚实

52. 作为灯带用户，我想刷到这一版固件后设备配置回默认值这件事被说明，这样我不会以为配置被吃掉。
53. 作为开发者，我想新灯效在旧固件上被明确拒绝而不是静默降级，这样不会出现两套行为。
54. 作为灯带用户，我想旧版小程序连新版固件时不会把灯写乱，这样升级顺序不影响安全。

## Implementation Decisions

### 基线与交付

- 基线是 `integration/ui-refactor-v4`（进阶编辑器与协议 v4 所在分支），新分支 `feat/strip-editor-polish`。
- **两次提交**，同一分支：①固件 + 协议文档 + 测试向量；②小程序编解码 + UI。每次都要跑固件 host 单测与向量校验脚本。

### 灯珠上限 100

- `MAX_LEDS` 64 → 100（固件常量、小程序常量、Kconfig 区间、占位文案同时改）。
- 线上布局**不变**：`start` / `end` 仍是 1 字节（100 < 255），`SetLedCount` 仍是 3 字节载荷，state blob 尺寸不变（已算过：v4 为 1440 字节，与灯珠数无关）。
- 固件要跟着改的缓冲：`led_engine` 的 TDM 帧缓冲 8×192 → 8×300（静态 RAM 约 +972 字节）、`led_render` 与 `led_strip_owner` 的栈帧 192 → 300。
- 时序代价（已实测推算）：单颗 30µs，8 条 ×100 颗单轮约 26ms（实测折算约 32ms）；20fps 下占用从 42% 升到约 65%，帧率上限从约 48fps 降到约 31fps。**这是接受的代价**，不为此提帧率。
- `effects.c` 里假设 `i ≤ 63` / `N ≤ 64` 的溢出推导要重新核对（结论：仍落在 uint32/uint64 内，但注释里的界要改）。

### 灯珠数编辑界面

- 设备信息页：每灯组一行滑块（`min=1 max=100 step=1`），拖动只更新本地值，`bindchange`（松手）才下发；页面顶部「总灯珠 n 颗」为各组合计。
- 灯组详情页：顶部一条当前组滑块，语义与上者相同。
- 下发路径复用现有 `setLedCount(value, stripId)`（ACK 超时 3000ms 不变）。
- **缩小灯珠数时先本地检查**该组现有光区与草稿：有越界则弹二次确认，确认后才下发并截断（越界光区截到新末尾、完全越界的删除；草稿里同步清理）。取消则不动设备也不动草稿。

### 时间轴

- 删除 `scroll-view` 包裹与 `timelineScrollable` / `MAX_ROW_SCALE` / `timelineRowWidth` 的「撑宽」语义。
- 新的分配规则（纯函数，替换现有水位法的行宽部分）：
  1. `available = 容器宽 - gap × (n-1)`；
  2. `gap` 先取 8px，若 `n × 24 + gap × (n-1) > 容器宽` 则改为 4px；
  3. 每块理想宽 = `available × dur / 总时长`；低于 **24px** 的块钉在 24px，剩余宽度在未钉住的块之间按时长重分配，重复至收敛；
  4. 若 24px 下限总和仍放不下，退化为**均分**（每块 `available / n`）。
- 块宽 < 48px 时不渲染时长文字。
- 块之间仍用 `flex` 布局，但宽度以 px 内联（`flex: <px> 0 0%`），保证「算出来的宽度」与「显示宽度」是同一份真相。

### 拖拽

- 长按阈值 `LONG_PRESS_MS` 380 → **300**。
- 拖动中：被拖块 `transform: translate(dx) scale(1.06)` + 投影 + `z-index` 抬高；落点之前的块与之间的块各 `transform: translateX(±blockWidth)`，过渡 150ms。
- 位移量由纯函数算出（`dragOffsetFor(from, to, widths)`），页面不做算术。
- 松手提交顺序，回弹；保留现有的「拖动后抑制一次 tap」逻辑。

### 光区轴与弹窗

- 轴：选中块 2px 主题色描边 + 两端圆形手柄（手柄宽 12px、高于条带 6px，用 `::before/::after` 或两个绝对定位元素，不改变块宽度）。轴下方文案「第 x–y 颗 · n 颗」。
- 弹窗：起点格加实心点与加粗数字，终点格加空心圆环，区间内格子加半透明主题底色；已有的「他人占用置灰」逻辑保持（纯逻辑层已拦，CSS 只是强化）。
- 数字滚轮：两个 `picker mode="selector"`。值域由**纯函数**给出——从锚点向两侧扩展，遇到被其它光区占用的序号即停，得到一段连续空闲 `[lo, hi]`；起点滚轮取 `[lo, anchor]`、终点滚轮取 `[anchor, hi]`（锚点未定时，起点取该段全部、终点禁用）。显示 1 基，内部 0 基。任一端变更立即重算网格预览与「确定」可用性。

### 方案（设备级、动态槽位）

- **草稿键改为 `deviceKey#slot`**（去掉 `stripId`）。方案内容是设备级事实，灯组只是编辑视角。
- 灯组页读取该设备的方案草稿，取出「当前灯组」的切片来显示；写入时只替换「当前步骤 × 当前灯组」那一片，其它灯组的切片原样保留（现有 `replaceStepZones` 语义不变，只是作用对象从「本组独立草稿」变成「设备级草稿的切片」）。
- 新建：取最小未占用 `script_id`（0–3），创建空方案（默认 1 步骤、无光区），选中它。
- 删除：二次确认 → 清本地草稿 → 发 `0x1E ClearScript(script_id)` → 刷新摘要。若设备命令失败，本地草稿保留并如实提示。
- **不重排编号**：显示的是「这个方案用的是第几号 `script_id`」。
- 页面上第一个方案默认是 `script_id = 0`；未点过「新建」时也只显示它一个。

### 协议 0x1E ClearScript

- 命令字 `0x1E`（原保留区），载荷 1 字节 `script_id`。
- 语义：清空该 id 的已提交剧本（`stage_count = 0`、`strip_count = 0`、所有段置空），若它正是激活剧本则退回 `NO_SCRIPT` 并停止播放。
- 未提交的 id 视为成功（幂等）。
- 结果码沿用现有集合：id ≥ `MAX_SCRIPTS` → `InvalidParam`；NVS 写失败 → `StorageFailed`。
- 不改协议版本号（v4 不变）。旧固件收到 `0x1E` 回 `UnknownCommand`。

### 三种新灯效

层编码形态不变（v3 8 字节 / v4 9 字节），参数块沿用现有 7 字节：

| 类型 | 值 | 参数（param[0..6]） |
|---|---|---|
| 爆闪 STROBE | `0x04` | `hue`(2) `sat`(1) `period_ms`(2) `duty`(1) `flags`(1：bit0 反向无效保留，bit1-7 = 0) |
| 心跳 HEARTBEAT | `0x05` | `hue`(2) `sat`(1) `period_ms`(2) `pulse`(1：脉冲宽度占比) `flags`(1：bit0 双脉冲开关，默认开) |
| 熄灭 OFF | `0x06` | `hue`(2, 恒 0) `sat`(1, 恒 0) `period_ms`(2, 恒 0) `p5`(1, 恒 0) `flags`(1, 恒 0) |

- **爆闪**：`period_ms` 即一个完整闪周期，**下限 100ms（10Hz 上限）**，`0` = 静止（不出光）。`duty` 0–255 表示亮的时间占比，界面上给「窄 / 中 / 宽」三档（约 15% / 35% / 60%）。包络用方波，两端各留 5% 线性斜坡避免硬切闪烁（与既有方波实现一致）。
- **心跳**：`period_ms` 为一个完整节拍，**下限 500ms（120 BPM 上限）、上限 1500ms（40 BPM 下限）**，`0` = 静止。包络为「双脉冲」：在一个节拍的前 30% 内出现两次短脉冲（大、小），其余时间为谷底；`pulse` 控制单次脉冲宽度（界面上不暴露，固定为中等）。
- **熄灭**：恒不出光，参数全 0。与「不画光区」的区别是**它在时间轴与光区轴上可见**，用户能明确表达「这一段就是黑的」。
- 频率上限受帧率约束的诚实说明：固件默认 20fps（每帧 50ms），10Hz 已是能表现的上界；**本次不提帧率**，因为 8×100 满负载下 40fps 会掉帧，掉帧看起来比低频更糟。
- 叠加层可选类型 = 静态 / 呼吸 / 彩虹 / 流光 / 爆闪 / 心跳（不含熄灭）。

### 固件与小程序要同步改的点

- 固件：类型枚举、参数长度表、已知/已实现表、校验（周期下限、保留位、熄灭层全零）、渲染分派、动画判定。
- 小程序：`SEGMENT_TYPE` 常量、`layerParamLength`、`writeLayer`、类型列表、参数控件映射。
- 文档与向量：`docs/effects-spec.md` 补三种类型；协议 v3/v4 文档补校验规则；重新生成两代向量。

### 简单档 9 张卡

- 原 6 张 + **爆闪白**（爆闪 / 白 / 中频 / 中占空）、**心跳暖红**（心跳 / 暖红 / 60 BPM）、**熄灭黑**（熄灭）。

### 渲染层（模拟器脚本）

在现有回归脚本上补四项，都是「只有渲染层能发现」的：

- 时间轴总宽不超过容器（不出现横向滚动）；
- 长按拖动后顺序真的变了，且拖动过程中有位移样式；
- 弹窗里被占用格点不动、滚轮里不出现被占序号；
- 新建 / 删除方案后设备摘要与 tab 同步变化。

### 页面与配置

沿用现有契约测试：新页面必须出现在页面列表、每个页面 `onLoad` 必须显式初始化私有字段、相对 import 不能指向目录。

## Out of Scope

- 提高动画帧率（20fps 保持）。爆闪上限 10Hz。
- 逐灯组亮度（协议仍只有全局亮度与逐组开关）。
- 渐变 / 淡入淡出（`fade` 能力位仍为 0）。
- 方案内容的设备端回读（仍只有 4 字节摘要）。
- 云端同步方案草稿。
- 灯珠数超过 100（需要把 `start`/`end` 改成 2 字节并整体换协议，收益不匹配）。
- 心跳的多段包络编辑（只给 BPM 一个旋钮）。

## Further Notes

### 三个必须先记住的陷阱

1. **相对 import 不能指向目录**。小程序解析器不认目录 `index`，在 App 启动链上会导致整页白屏，`tsc` 与单测都发现不了。
2. **`Page({})` 只保证 `data` 里的字段出现在 `this.data`**。对象字面量上的私有字段运行时是 `undefined`，它会在 `onLoad` 链上抛错并中断整页事件绑定，表现是「点什么都没反应」。每个页面 `onLoad` 开头必须显式初始化全部私有字段。
3. **写整组前必须先清掉该组其它光区**。协议要求同带光区不重叠，不清会被回 `InvalidParam`，用户点了卡片却毫无变化。

### 本轮新增的第四条（结构性问题，不是白屏，是数据静默串档）

方案在设备上是**设备级**的 4 个 `script_id`，一个 id 覆盖所有灯组。当前草稿按键里带了 `stripId`、写入时又把槽位号直接当 `script_id`，导致不同灯组的同一槽位互相覆盖。这次的键改造必须一次做对，否则槽位浮动后问题更难发现。

### 断崖升级的告知

刷到含 `MAX_LEDS = 100` 与三种新灯效的固件后，设备配置回默认值（与 v2→v3、v3→v4 一致）。界面与文档必须写明，验收记录也要记一笔。

### 交付顺序

1. **固件 + 协议**：`MAX_LEDS`、三种灯效、`0x1E ClearScript`、文档、两代向量、host 单测。
2. **小程序编解码**：类型常量、长度表、写入、`0x1E` 指令。
3. **UI**：灯珠数滑块、固定宽度时间轴、拖拽动画、光区手柄与滚轮、设备级动态方案、7 类型 / 9 张卡。

第 1、2 步可先合；第 3 步依赖第 2 步的编解码，不能单独检出用旧固件跑新效果。
