## Parent

#71（规格：灯组进阶编辑器打磨）

## What to build

把「设置灯珠数」从「选灯组 → 打数字 → 点应用」改成**每组一条滑块**，并在编辑器里也能改当前组。

**设备信息页**：每个灯组一行，一条 1–100 的滑块，拖动只改本地值，松手才下发（设备重建灯带句柄的 ACK 上限是 3 秒，不能逐帧发）。页面顶部显示**总灯珠数**——各灯组灯珠数之和，只读。

**灯组详情页**：顶部一条当前灯组的灯珠数滑块，语义相同。用户在编辑时发现这条实际是 48 颗而不是 60 颗，就地改掉，不用退两层页面。

**改小时不能静默丢编排**：缩小灯珠数之前先在本地检查这条灯组现有的光区与草稿，有越界的先提示「有 n 个光区超出新长度」，用户确认后才下发并把越界部分截到新末尾、完全越界的删除，草稿里同步清理。点取消则设备与草稿都不动。

## Acceptance criteria

- [ ] 设备信息页每条灯组各有一条滑块，拖动时数字实时变，松手才下发
- [ ] 设备信息页顶部显示的总灯珠数等于各灯组灯珠数之和
- [ ] 灯组详情页顶部能改当前组的灯珠数并就地生效，不影响其它灯组
- [ ] 滑块范围是 1–100，到不了 0，也超不过 100
- [ ] 把灯珠数改小且已有光区越界时，先出现带数量的确认提示，取消则设备与草稿都不变
- [ ] 确认后越界光区被截到新末尾、完全越界的被删除，草稿同步清理，灯组仍能正常应用并播放
- [ ] 把灯珠数改大时不会改动任何已有光区
- [ ] 下发失败时就地显示原因，并保留原灯珠数
- [ ] 单元测试覆盖「缩小越界时的截断计划」：部分越界、完全越界、无越界、改大四种输入
- [ ] 渲染层回归覆盖滑块存在、总数正确、确认流程走通
- [ ] 固件 host 单测、小程序单测与类型检查全部干净
