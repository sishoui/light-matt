## Parent

#71（规格：灯组进阶编辑器打磨）

## What to build

修掉一个既有的数据串档问题：**两条灯组的同一方案槽位会互相覆盖**。

设备上的方案是**设备级**的，固定四个编号，一套方案覆盖所有灯组。但当前草稿是按「设备 + 灯组 + 槽位」存的，写入时又把槽位号直接当作设备的方案编号。于是灯组 A 的方案① 和灯组 B 的方案① 都写到设备上的同一个编号，后写的会把前一个覆盖掉，另一条灯组在那套方案里直接变成全暗。用户看到的现象是「我明明给第二组也编了，播放时它不亮」。

把方案的归属改成设备级：草稿按「设备 + 槽位」存，不再带灯组。灯组页读的是这套方案里「当前灯组」的那一片，写入时也只替换「当前步骤 × 当前灯组」那一片，其它灯组的切片原样保留。

这一步只改归属与存取，界面表现不变（槽位仍是四个固定坑，下一张票才改成动态）。已有本地草稿要处理：旧键里的灯组维度去掉之后，若多组都有同一槽位的草稿，取灯组号最小的那份作为初始内容，其余丢弃——一次性迁移，不做长期双读。

## Acceptance criteria

- [ ] 在灯组 A 的方案① 里编排后，切到灯组 B 的方案①，看到的是 B 自己的内容（或空白），不是 A 的
- [ ] 在灯组 B 的方案① 里写入并播放，灯组 A 在这套方案里的内容保持原样
- [ ] 一套方案里同时包含多个灯组的编排时，播放能同时呈现两条灯组的画面
- [ ] 切换灯组时方案内容不会串档，也不会因切换而清空
- [ ] 旧版本地草稿能平滑迁移：同一槽位有多组内容时取灯组号最小的，其余丢弃，不做长期双读
- [ ] 断开重连、退出重进页面后，设备级的方案内容仍在
- [ ] 删除设备时能清掉这台设备的全部方案草稿
- [ ] 单元测试覆盖：键形状变更、按灯组切片读写、多组互不影响、旧键迁移取最小灯组号
- [ ] 渲染层回归覆盖：两条灯组各自编辑同一槽位后互不覆盖
- [ ] 固件 host 单测、小程序单测与类型检查全部干净
