## Parent

#71（规格：灯组进阶编辑器打磨）

## What to build

把「四个永远占着的方案坑」改成按需增长的槽位。

进入页面**只显示一个方案**，没有内容时标「空白」。点「+ 新建方案」占用下一个未被使用的设备方案编号，最多四个；四个都在用时按钮不可用。每套方案可删除，**删除后不重排编号**——删掉②就剩①③④，显示的就是它们各自的编号，这样设备上的方案不会因为删一套而整体搬家。

删除要真的从设备上清掉，不能只删本机草稿。为此本票接上「清空方案」这条命令：二次确认后先清本地草稿、再让设备清空该编号、最后刷新摘要。设备侧清空失败时，本机草稿要保留并如实提示，不能出现「本机没了但设备还在」的静默不一致。

每个方案 tab 上显示「空白」或「n 步」，让用户知道哪套有内容。

## Acceptance criteria

- [ ] 首次进入只看到一个方案，没有内容时标注「空白」
- [ ] 点「+ 新建方案」新增一套并选中它，编号取当前未被使用的最小值
- [ ] 四套都在用时「+ 新建方案」不可用
- [ ] 每套方案都能删除，删除前有二次确认
- [ ] 删除后设备上该编号的方案确实被清空（摘要变空白），其它方案内容不受影响
- [ ] 删除后编号不重排：删掉②后剩下的是①③④
- [ ] 删除正在播放的那套方案时，播放停止
- [ ] 删除被设备拒绝时就地显示原因，本机草稿保留
- [ ] 每个方案 tab 显示「空白」或「n 步」
- [ ] 切换方案后，时间轴、光区、效果面板整体跟着切换
- [ ] 界面上不出现协议词与内部编号（不用「槽位」「script_id」这类词）
- [ ] 单元测试覆盖：最小空位分配、上限四、删除后不重排、空表起步只有一套、删除后再次新建能复用该编号
- [ ] 渲染层回归覆盖：新建与删除后 tab 与设备摘要同步变化
- [ ] 固件 host 单测、小程序单测与类型检查全部干净
