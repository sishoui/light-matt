# 01: 路由与页面骨架

## Parent

#60

## What to build

底部只剩「设备 / 我的」两项，用户从设备页右上角的菜单进发现页，而不是把发现当成一个 tab。

设备页右上角的「发现」普通按钮改成一个下拉菜单，菜单项为「添加设备（扫描）/ 设备信息 / 断开连接」；其中「添加设备」跳到新的发现页，「设备信息」跳到现有的设备信息页，「断开连接」按当前连接状态可用。新增「我的」tab 页和「灯组详情」二级页两条空路由，能进能出，内容留待后续票填充。

这一票只建立骨架：路由常量、页面配置、tabBar 两项、菜单展开与关闭、空页面的返回。设置项搬家、设备页瘦身、灯组编辑都在后面的票里。

## Acceptance criteria

- [ ] 底部 tabBar 只有两项，文案是「设备」和「我的」，第二项图标是人物轮廓（仍为纯 CSS，不引入位图）
- [ ] 点设备页右上角按钮展开菜单，点遮罩或再次点按钮收起；菜单三项都能触发对应动作
- [ ] 菜单里的「断开连接」在未连接时不可用，已连接时可断开并回到未连接状态
- [ ] 新的发现页、我的页、灯组详情页都存在，能被正常打开并返回，不白屏、不报错
- [ ] 路由常量的 tab 列表与页面配置里的 tabBar 列表完全一致，新增页面出现在页面列表里
- [ ] 每个新页面的页面实例在加载时显式初始化了全部非 datat 字段（避免点不动）
- [ ] 相对 import 没有指向目录（避免启动链白屏）
- [ ] 改版回归脚本覆盖新的两项 tabBar 与菜单展开/收起
- [ ] 类型检查与全部单元测试保持干净

## Blocked by

None（可立即开始）
