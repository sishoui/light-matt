# 03: 设备页瘦身

## Parent

#60

## What to build

设备详情页从「设备级 + 灯组级混在一屏」收窄成只管设备级的页面。

**顶部**：设备名称、连接状态、整台设备的总开关、整台设备的亮度滑块（上限取设备上报的亮度上限，界面显示百分比）。

**中间**：灯组两列卡片网格。每张卡片显示灯组序号、灯珠数、当前效果摘要，以及一个该灯组的开关。卡片上的开关直接切换这一条灯组的独立开关，不进入详情；点卡片主体进入灯组详情页。只显示启用掩码内的灯组。

**底部**：只读的设备摘要（固件版本、硬件号、灯组数、灯珠总数）和一个进设备信息页的入口。

设备页不再出现任何灯效编辑控件（效果卡、段落、光区、参数），也没有逐灯组亮度——协议只有全局亮度与逐组开关。

## Acceptance criteria

- [ ] 设备页顶部能开关整台设备，能拖动整体亮度并真实下发
- [ ] 灯组以两列卡片呈现，每张卡显示灯组号、灯珠数、效果摘要与该组开关
- [ ] 卡片开关只影响那一条灯组，其他灯组继续运行（逐组独立的开关掩码）
- [ ] 点卡片开关不会进详情页，点卡片主体会进该灯组的详情页并带上灯组号
- [ ] 被隐藏的灯组不在卡片里出现
- [ ] 设备页底部摘要显示固件版本、硬件号、灯组数、灯珠总数，全部只读
- [ ] 设备页底部入口能进设备信息页
- [ ] 设备页上不存在效果卡、光区、效果参数、叠加方式等编辑控件
- [ ] 深度回归脚本改为在新设备页上验证电源、整体亮度、逐组开关、进灯组页
- [ ] 类型检查、全部单元测试、渲染层回归脚本全部干净
