# 08: 协议 v4 · 契约、向量与固件

## Parent

#60

## What to build

协议升到 v4：层编码多一个字节，让每一个光区有自己的亮度档位。

**新字段**：层编码从八字节扩到九字节，新增的第九字节是 `level`，取值零到一百（一百档，零表示这一层不出光）。超过一百的值一律按参数非法拒绝。空层的 `level` 必须为零。静态层原本「参数第三到第六字节必须全零」的规则保留，`level` 是独立字节不受它约束。

**语义**：`level` 是这一层的母亮度，与设备整体亮度在用户空间相乘，之后才做 gamma。呼吸结构的「最低亮」改为相对百分比：实际谷底等于这一层的 `level` 乘以最低亮百分比。

**尺寸连带变化**：设置单段载荷、脚本单段载荷、段报告、状态存储的段记录与总长都要跟着改；帧上限不变。

**兼容**：新固件收到旧版本帧时明确回「版本不支持」，不做双版本解码。刷机后设备配置回到默认值，与上一代升级的处理方式一致。

需要同时更新：协议文档的字节布局与校验规则、跨端测试向量的生成与校验、固件四处的形状校验与合成路径、固件宿主单测。

## Acceptance criteria

- [ ] 协议文档写清九字节层布局，并把新增字段的取值范围、空层规则、拒绝条件写进校验规则
- [ ] 固件接受带亮度的新帧，零档、五十档、一百档都能正确出光
- [ ] 超过一百的亮度被拒绝并回参数非法
- [ ] 空层的亮度必须为零，否则被拒绝
- [ ] 呼吸结构的谷底等于这一层的亮度乘以最低亮百分比
- [ ] 整体亮度与光区亮度按乘积生效，且 gamma 只做一次
- [ ] 新固件收到旧版本号的帧时回「版本不支持」，且能正常继续服务后续帧
- [ ] 状态存储的编码长度与解码版本校验同步更新；旧版本存储整体拒绝、不出现半套加载
- [ ] 跨端测试向量重新生成，三端（固件、小程序编解码、向量校验脚本）对同一批向量一致
- [ ] 固件宿主单测全部通过，新增亮度相关的边界用例
- [ ] 刷机后设备配置回到默认值这一行为在验收记录里写明
