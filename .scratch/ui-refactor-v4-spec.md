## Problem Statement

用户想改灯，但小程序把这件事拆散在四个地方，而且没有一处是「按灯带想事情」的。

**导航层面**：底部两个 tab 是「设备 / 发现」。发现页同时装着扫描、我的设备、备注改名、灯组显示开关、外观主题、演示设备开关、版本号和隐藏的协议日志面板。一个临时动作（找设备）和一堆长期设置挤在同一页，两者互相干扰。

**设备层面**：进入某台设备后，用户看到的是一屏混合体——顶部灯组 chips、总闸、单组开关、全局亮度、快捷/自定义两档编辑器、当前灯效摘要、设备信息入口。设备整体的信息（固件号、硬件号、灯组数）藏在二级页，而「这台设备有几条灯带、每条在播什么」这件最该一眼看到的事反而没有。

**编辑层面**：多阶段编排是一屏塞三层——方案槽位 tabs → 步骤列表（上移/下移/删）→ 每条光区一整串内联控件（4 种模式 + 一排固定色块 + 叠加开关 + 混合方式），中间还夹着一条 64 格灯珠网格。用户无法回答三个基本问题：这一步播多久？这条光带在这一步被分成几段？每段多亮？

**亮度层面**：协议只有全局亮度一个字节，每条灯带只有开关；光区（段）没有任何亮度字段，静态层剩下的 4 个字节是保留位且固件强制必须为 0。用户「这一段暗一点」这个最自然的需求，硬件层面根本无法表达。

## Solution

### 导航重排

底部两个 tab 变成 **设备 / 我的**。

- **设备（tab 1）**：保留现在的 1:1 大卡 + 其他设备小图。右上角「发现」普通按钮改成一个**下拉菜单**，菜单项是「添加设备（扫描）/ 设备信息 / 断开连接」。设备信息从菜单进。
- **我的（tab 2，新建）**：头像与昵称（只存本机）、外观、演示设备、我的设备（删除）、版本号（连点 5 次开协议日志）。
- **发现（二级页，新建）**：只有一个扫描按钮、一行状态、一个扫描结果列表。没有「我的设备」、没有外观、没有演示开关。
- **设备详情页（二级页）**：顶部是设备名称、状态、**设备整体总开关**、**设备整体亮度**；中间是**灯组两列卡片**（每张卡带该组开关和当前效果摘要）；底部是设备摘要（固件、硬件号、灯组数、灯珠总数）和一个进「设备信息」的入口。
- **灯组详情页（二级页，新建）**：顶部只有灯组名和「方案 ①」按钮（原「信息」按钮删除）；下面是 **简单 / 进阶** 分段控件。

### 灯组详情页

**简单**：6 张成品效果卡（常亮 / 呼吸 / 彩虹 / 流光 / 闪烁 / 警灯），点一下整组统一变；参数区是色相、饱和度、亮度三个滑块。语义仍是「整组覆盖成一个效果」。

**进阶**（自上而下，箭头串联，说明每一层都是上一层的细化）：

```
时间轴          ← 按真实时长比例分块，最短 40px 保底可点
                 长按 380ms 可拖动换顺序；「+ 加一段」，最多 8 段
   ↓
时长拖拽条      ← 0.5–30 秒，最小单位 0.5
   ↓
光区分段轴      ← 按灯珠比例分块，未覆盖处显示为灰条
                 点块选中该光区；「+ 新增」，最多 8 个
   ↓
效果面板        ← 效果类型在最上（静态/呼吸/彩虹/流光），
                 下面的参数随类型整体替换；颜色统一用 HSV 滑块
```

**灯珠方格不进主界面**，只在弹窗里出现：点「+ 新增」或点已有光区的范围时弹出，一次显示该灯组全部灯珠格子（有几颗画几颗）。点第一颗、再点第二颗选中区间；已被其他光区占用的格子置灰且不可点；与已有光区重叠时当场报错、不落草稿。

**底部只有一个按钮**：`应用并播放`。有未写入的改动时自动先写入再播放；只想写入不播放的场景通过该按钮的二次确认实现。

### 协议 v4：逐光区亮度

层编码从 8 字节扩到 **9 字节**，新增 `level`：

```
偏移  宽  字段
0     1   type
1..7  7   param（语义不变）
8     1   level   0–100（100 档；0 = 不亮；>100 视为非法）
```

`level` 是这一层的**母亮度**，与全局 `brightness` 在用户空间相乘（gamma 之前）。呼吸层的 `minLevel` 语义改为**相对百分比**：谷底 = `level × minLevel%`。

v4 固件**拒收 v3 帧**并回 `UnsupportedVersion`——断崖升级，刷机后设备配置回到默认值，与 v2→v3 的处理一致。

## User Stories

### 导航与整体结构

1. 作为灯带用户，我想在底部只看到「设备」和「我的」两个入口，这样我不用在「发现」里翻设置。
2. 作为灯带用户，我想从设备页右上角的菜单里添加新设备，这样扫描不再占用一个 tab。
3. 作为灯带用户，我想在同一个菜单里直接进设备信息或断开连接，这样常用操作不用绕路。
4. 作为灯带用户，我想在「我的」里看到自己的头像和昵称，这样应用有一点「这是我的」的感觉。
5. 作为灯带用户，我想在「我的」里切换浅色 / 深色 / 跟随系统，这样晚上调灯不刺眼。
6. 作为灯带用户，我想在「我的」里开关演示设备，这样没有硬件时也能看到界面。
7. 作为灯带用户，我想在「我的」里删除一台不再使用的设备，这样列表不会越积越长。
8. 作为灯带用户，我想在「我的」底部看到版本号，这样我知道自己装的是哪一版。
9. 作为开发者，我想连点版本号 5 次打开协议日志，这样现场排查不用改代码。
10. 作为灯带用户，我想发现页只有一个扫描按钮和结果列表，这样我一眼就知道该点哪里。

### 设备页

11. 作为灯带用户，我想在设备页顶部看到这台设备的名称和连接状态，这样我确认自己在控制哪一台。
12. 作为灯带用户，我想在设备页顶部有一个整台设备的总开关，这样我可以一键全灭。
13. 作为灯带用户，我想在设备页顶部拖动整台设备的亮度，这样所有灯组一起变亮变暗。
14. 作为灯带用户，我想看到这台设备有几条灯组，以两列卡片的形式排列，这样我一屏就能掌握全部灯组。
15. 作为灯带用户，我想在每张灯组卡片上直接开关那一条灯组，而不用先进去，这样我能快速灭掉不想亮的那一条。
16. 作为灯带用户，我想在每张灯组卡片上看到它当前的灯效摘要和灯珠数，这样我不用点进去也知道它在播什么。
17. 作为灯带用户，我想点灯组卡片进入它的详情页，这样我在那一条灯组上编辑灯效。
18. 作为灯带用户，我想在设备页底部看到固件版本、硬件号、灯组数和灯珠总数，这样我不用跳页就能确认设备身份。
19. 作为灯带用户，我想从设备页底部进入设备信息页，这样我能重命名、自检、删除或改灯珠数。
20. 作为灯带用户，我想某条灯组不可见时不显示在卡片里，这样我看不到不存在的灯组。

### 灯组详情页

21. 作为灯带用户，我想在灯组页顶部看到灯组名称和所属设备，这样我不会编错灯组。
22. 作为灯带用户，我想在灯组页用「简单 / 进阶」切换编辑深度，这样我按需要选择理解成本。
23. 作为灯带用户，我想在进阶模式点「方案 ①」切换到另外三个方案槽位，这样我能保存多套编排。
24. 作为灯带用户，我想在时间轴上一次看到这一段占多少时间（按比例宽度），这样我能直观看到节奏。
25. 作为灯带用户，我想点时间轴上的一段就选中它，这样我能针对那一段调时长和光区。
26. 作为灯带用户，我想长按时间轴上的一段并拖动改变顺序，这样我不用点上下移按钮。
27. 作为灯带用户，我想点「+ 加一段」新增一段，这样我能延长编排。
28. 作为灯带用户，我想拖动时长条在 0.5–30 秒之间调整这一段，这样我能精确设定节奏。
29. 作为灯带用户，我想时间轴块再短也点得到（有最小宽度），这样我不会因为设成 0.5 秒就点不中。
30. 作为灯带用户，我想在光区分段轴上看到这条灯带被分成了几段、哪段没覆盖，这样我知道还有没有暗区。
31. 作为灯带用户，我想点「+ 新增」打开灯珠格子弹窗来划出新光区，这样我不会误触多出空光区。
32. 作为灯带用户，我想在弹窗里点第一颗灯珠再点最后一颗就选中中间全部灯珠，这样我不用逐颗点。
33. 作为灯带用户，我想在弹窗里看到已被别的光区占用的灯珠是灰的且点不动，这样我不会画出重叠。
34. 作为灯带用户，我想在弹窗里看到重叠时立刻报错，这样我不会写出设备会拒绝的配置。
35. 作为灯带用户，我想在弹窗里删除一个光区，这样我能取消不需要的分段。
36. 作为灯带用户，我想先选效果类型（静态/呼吸/彩虹/流光），再调它专属的参数，这样我不会看到用不上的旋钮。
37. 作为灯带用户，我想用色相滑块选颜色，这样我能得到任意颜色而不只是几个预设。
38. 作为灯带用户，我想用饱和度滑块调整颜色的浓淡，这样我能从鲜艳到接近白色。
39. 作为灯带用户，我想用亮度滑块调整这一段的亮度，这样我能让某一段比别的段暗。
40. 作为灯带用户，我想给呼吸加周期、最低亮度和波形，这样我能调出不同的呼吸感。
41. 作为灯带用户，我想给彩虹加周期、跨度和方向，这样我能控制颜色流动的快慢和范围。
42. 作为灯带用户，我想给流光加周期、尾长和方向，这样我能控制光点跑的形态。
43. 作为灯带用户，我想点「应用并播放」一步到位，这样我不用先写入再播放。
44. 作为灯带用户，我想在简单档点一张效果卡就让整组统一变，这样我不用理解分段。
45. 作为灯带用户，我想在简单档调整色相/饱和度/亮度作用于整组，这样我能微调整体观感。
46. 作为灯带用户，我想在进阶档编辑当前灯组时别的灯组不受影响，这样我在多灯组设备上不会误改。
47. 作为灯带用户，我想在方案内容为空时看到引导而不是一片空白，这样我知道下一步做什么。
48. 作为灯带用户，我想被告知方案内容只存在这台手机上，这样我换手机时不会以为数据丢了。

### 协议与硬件

49. 作为灯带用户，我想让每一段灯珠有独立的亮度档位（100 档），这样我能在一套编排里做出明暗对比。
50. 作为灯带用户，我想光区亮度与设备整体亮度叠加生效，这样我既能整体调暗又能局部更暗。
51. 作为灯带用户，我想呼吸的最低亮度是相对这一段的百分比，这样两个旋钮的语义不冲突。
52. 作为灯带用户，我想升级固件后旧配置被重置这件事在界面上被说明，这样我不会以为配置被吃掉。
53. 作为开发者，我想 v4 固件明确拒绝 v3 帧，这样不会出现两套解码路径长期并存。

## Implementation Decisions

### 术语

- 继续用 **灯组** 作为用户界面词（#58 已统一「灯带数 → 灯组数」），物理介质在文档里仍叫灯带。
- **光区** = 协议里的段；**步骤** = 阶段；**方案** = 剧本。界面不出现段 / 阶段 / 剧本 / 下发 / 激活 / 毫秒。
- 灯珠从 0 编号只在弹窗提示里出现一次；主界面用区间文本（如 `0–19`）。

### 页面职责与路由

| 路由 | 角色 | 关键约束 |
|---|---|---|
| 设备（tab 1） | 浏览与切换 | 点小图只切大卡不连接；点大卡进设备页；卡上电源键是 `catchtap` |
| 我的（tab 2，新建） | 设置与身份 | 不含任何设备控制 |
| 发现（二级页，新建） | 只管扫描 | 不承载设置；结果列表复用 `known` 标记 |
| 设备详情（二级页） | 设备级控制 | 总开关 + 全局亮度 + 灯组卡片 + 设备摘要 |
| 灯组详情（二级页，新建） | 单组编辑 | 从设备页灯组卡片进入，携带灯组号 |
| 设备信息（二级页） | 身份与危险操作 | 自检 / 改名 / 删除 / 逐组灯珠数留在这一页 |

删除「发现」作为 tab 的原页面。tabBar 第二项图标从雷达改为人物轮廓，仍为纯 CSS。

### 设备页

- 顶部：名称、连接状态、总电源、全局亮度滑块（上限取设备上报的 `max_brightness`，界面显示百分比）。
- 灯组卡片：两列网格；内容为灯组序号、灯珠数、当前效果摘要、开关。开关是 `catchtap`，只切该组 `strip_power_mask`，不进入详情。卡片主体点击进入灯组页。
- 只显示启用掩码内的灯组（沿用现有逐组可见性偏好）。
- 底部摘要：固件版本、硬件号、灯组数、灯珠总数（全部只读）。
- 设备页**不再有**任何灯效编辑控件，也没有逐灯组亮度。

### 灯组详情页 · 简单档

- 6 张成品效果卡，沿用现有快捷卡的数据模型（含每卡支持的参数集合）。
- 语义仍是整组覆盖：写入前先清掉该组其它光区，避免设备回 `InvalidParam`。
- 参数区固定三项：色相、饱和度、亮度，全部 HSV 滑块。

### 灯组详情页 · 进阶档

**时间轴**

- 每段一个块；宽度按 `dur / maxDur` 比例分配，`flex-grow = dur`、`flex-basis = 0`、`min-width = 40px`。最小宽度是硬要求：0.5 秒的段在 8 段并列时仍必须可点。
- 点击切换当前段；长按 380ms 进入拖动，横向拖动到别的块上即交换顺序，松手结束。
- 「+ 加一段」新建空段（默认 1 秒、无光区）并选中它；上限 8 段。
- 段块内部用该段光区的颜色按比例铺成色带，作为这一段的缩略预览。

**时长拖拽条**

- 范围 0.5–30 秒，步进 0.5；下方三档刻度（0.5 / 15 / 30 秒）。
- 拖动时时间轴块宽实时变化，不重建整页。

**光区轴**

- 按灯珠下标比例定位每个光区块（`left = start/ledCount`，`width = (end-start+1)/ledCount`）。
- 未被任何光区覆盖的区间画成灰条，让「还有暗区」可见。
- 点块选中；选中态用 2px 描边而不是改变颜色，避免与光区自身颜色混淆。
- 「+ 新增」只在未覆盖区间上工作；上限 8 个光区。

**灯珠格子弹窗**

- 一次渲染该灯组全部灯珠（`ledCount` 颗，最多 64），12 列网格。
- 第一次点击设锚点，第二次点击确定区间（自动取 min/max）。
- 属于其它光区的格子渲染为置灰且 `disabled`。
- 与其它光区重叠时立刻显示错误文案并保留弹窗，不写草稿。
- 「确定」提交区间并关闭；「删除」仅对已有光区可用；「取消」丢弃本次改动。
- 同一颗灯珠点两次视为取消，不产生 1 颗灯珠的光区。

**效果面板**

- 效果类型行在最上，四个等宽按钮：静态 / 呼吸 / 彩虹 / 流光。
- 参数区按类型整体替换：

| 类型 | 参数 |
|---|---|
| 静态 | 色相、饱和度、亮度 |
| 呼吸 | 色相、饱和度、亮度、周期、最低亮、波形（正弦/三角/锯齿/方波） |
| 彩虹 | 周期、跨度、方向（正转/反转） |
| 流光 | 色相、饱和度、亮度、周期、尾长、方向 |

- 颜色一律用 HSV 滑块：色相 0–360（滑轨显示彩虹渐变），饱和度 0–100，亮度 5–100（100 档）。
- 每个滑块右侧显示当前数值与单位；数值用等宽数字。
- 拖动过程中只更新本地草稿与预览色块，不逐帧写设备。

**底部动作**

- 只有一个主按钮「应用并播放」。点击时若有未写入改动，先写入再播放；写入失败则在按钮下方就地显示原因。

### 方案槽位

- 顶部右侧一个按钮显示当前槽位（如「方案 ①」），点击在 ①–④ 之间轮换。
- 空槽位可见且标注为空白——「设备上有 4 个坑」是用户需要知道的事实。
- 有内容的槽位显示步骤数摘要。

### 方案内容不可回读的告知

设备只回「几个步骤、是否启用、是否循环」，步骤时长与光区内容无法读回。灯组页必须在进阶档显示这一事实：内容仅存在本机，换机或清缓存后需要重新编排。

### 多灯组语义

进阶档只编辑**当前灯组**在这一步的那一片光区，其它灯组原样保留。写入时按「当前步骤 × 当前灯组」替换，不整体覆盖步骤。

### 协议 v4

层编码 9 字节：`type(1) + param(7) + level(1)`。

新增字段语义：

- `level` 取值 0–100；`> 100` 一律 `InvalidParam`（保留 101–255 给未来更细档位，但不接受）。
- `level = 0` 合法：该层不出光（但类型仍参与校验）。
- 空层（`type = 0xFF`）的 `level` 必须为 0，与「空层其余字节必须为 0」的现有规则一致。
- 静态层校验从「`param[3..6]` 必须全 0」保留；`level` 是独立字节，不受该规则约束。
- 呼吸层的 `minLevel` 语义变为相对百分比：实际谷底 = `level × minLevel / 100`。
- 合成顺序：两层各自按 `level` 缩放 → 按 blend 合成 → 乘全局 `brightness` → gamma。

尺寸变化：

| 项 | v3 | v4 |
|---|---|---|
| 层编码 | 8 | 9 |
| SetSegment 载荷 | 21 | 22 |
| ScriptSegment 载荷 | 23 | 24 |
| SegmentReport | 21 | 22 |
| State blob 段记录 | 20 | 22 |
| State blob 总长 | 1312 | 1440 |
| 帧上限 | 240 | 不变 |

兼容策略：v4 固件收到 `version = 0x03` 的帧回 `UnsupportedVersion`；不做双版本解码。刷机后设备配置回到默认值。

### 身份（本机）

- 头像用 `open-type="chooseAvatar"`，昵称用 `<input type="nickname">`，两者只写本机存储；默认昵称「微信用户」，默认头像是纯 CSS 占位。
- 不调用已下线的 `getUserProfile`。
- 不上传头像或昵称到后端；后端 `users` 表已有昵称列，接口保留但本轮不接。

## Testing Decisions

### 什么算好测试

只测外部行为：给定输入（草稿、手势、字节流），断言可观察的输出（新的草稿、帧字节、渲染出的视图模型）。不测私有字段、不测 DOM 结构细节、不测实现顺序。

### 新增缝（两个纯函数模块）

**时间轴编辑**：时长钳位到 0.5–30 与 0.5 步进、段宽比例、最小宽度在极端分布下不破坏比例语义、按索引重排（含越界与自身拖动）、上限 8 段、加段后新段被选中。

**光区轴**：按灯珠数与区间算出百分比定位、未覆盖区间的空隙列表、两区间重叠判定、边界（单颗光区、整条覆盖、零光区）。

两者的先例分别是 `plan-editor.test.ts` 与 `zone-editor.test.ts` / `effect-layout.test.ts`：纯函数、直接构造输入、断言数组/区间，不涉及 wx。

### 修改的现有缝

- **光区草稿 ↔ 协议 spec 的转换**：新增 `level` 后，装配函数必须保证空层的 `level` 为 0、非空层的 `level` 落在 0–100。现有 `zone-model.test.ts` 已锁同类约束（空层叠加方式归一），扩展即可。
- **方案草稿按灯组切片替换**：现有 `plan-editor.test.ts` 已锁「替换当前组不动别组」，v4 只是字段增加，断言补充 `level`。
- **字节编解码**：现有 `codec.test.ts` 与跨端向量是唯一真缝。v4 需要重新生成向量文件，并让固件与小程序共用同一批向量。

### 固件

- 现有 host 单测（11053 项断言）继续作为字节与效果语义的守门人；v4 增加 `level = 0 / 50 / 100` 与「大于 100 被拒」的用例。
- 效果函数新增「按 level 缩放」的纯函数测试（呼吸谷底 = `level × minLevel%`）。
- State blob 编解码新增长度与版本拒绝用例（v3 blob 必须整体拒绝）。

### 渲染层

四个模拟器脚本继续兜底，并按新结构改写：

- 页面树、大卡、小图切换、主题、tabBar 两项 → 改版回归脚本。
- 点得动（所有 `bindtap` 有实现） → 交互回归脚本。
- 快捷卡生效 / 参数区 / 切分 / 快照恢复 / 逐组灯珠数 / 术语 / 两 tab → 灯效编辑回归脚本，改为面向灯组页。
- 电源 / 亮度 / 自定义档 / 写入 / 播放 → 深度回归脚本。

新增必须覆盖的渲染项：时间轴长按重排后顺序真的变了、灯珠弹窗里被占用的格子真的点不动、光区重叠真的不产生新区间、切换效果类型后参数区真的整体替换。

### 配置层

现有配置契约测试继续要求：新页面必须出现在页面列表、tabBar 项必须与路由常量一致、每个页面的 `onLoad` 必须显式初始化私有字段、相对 import 不能指向目录。

## Out of Scope

- 多设备同时连接与多设备分组控制（硬件只有一台）。
- 云端同步头像、昵称、方案内容（方案内容设备不回读，本机存）。
- 后端身份体系改动、隐私指引与域名备案（上线前独立工作）。
- 逐灯组亮度（协议只有全局亮度与逐组开关，本次只做逐光区亮度）。
- 渐变 / 淡入淡出（`fade` 能力位当前为 0，固件未实现）。
- 账号体系、登录页、多用户。
- 灯效库的市场化分享与导入导出。

## Further Notes

### 三个必须先记住的实现陷阱

1. **相对 import 不能指向目录**。小程序的模块解析器不认目录 `index`，在 App 启动链上会导致整个小程序白屏，而 `tsc` 与单测都发现不了。
2. **`Page({...})` 只保证 `data` 里的字段出现在 `this.data`**。写在对象字面量上的私有字段运行时是 `undefined`，在 `onLoad` 调用链上会抛错并中断整页事件绑定，表现是「点什么都没反应」。每个页面的 `onLoad` 开头必须显式初始化全部私有字段。
3. **快捷档写整组前必须先清掉其它光区**。协议要求同带光区不重叠，不清就会被回 `InvalidParam`，用户点了卡片却毫无变化。

### 交付顺序

四个 PR，前三个是 UI 重构，第四个是协议：

1. **路由与骨架**：新增发现 / 我的 / 灯组三条路由，删除原发现页，tabBar 改两项，路由常量与配置契约测试同步。
2. **发现页 + 我的页**：扫描精简、设置整体搬迁、设备管理、协议日志、本机头像昵称。
3. **设备页 + 灯组页**：设备页瘦身、灯组两列卡片、简单档与进阶档编辑器（时间轴、光区轴、灯珠弹窗、HSV 参数）。此阶段光区亮度滑块带「固件更新后可用」标记。
4. **协议 v4**：协议文档、测试向量、固件、小程序编解码、真机验收。独立分支，可与前三个并行但只能最后合。

每个 PR 内同步更新受影响的模拟器回归脚本，保证任何一个 PR 单独检出都能跑绿。

### 交互原型

进阶编辑器的三版对比与最终版（时间轴 + 光区轴 + HSV 参数 + 灯珠弹窗）已在设计讨论中做出可交互原型，最终版结构与本文一致。
