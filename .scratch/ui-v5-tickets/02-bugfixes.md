## Parent

#85（规格：小程序 UI / 交互第五轮）

## What to build

三个互相独立、但都表现为「点了没反应 / 过一会儿才反应」的修复。

**删除设备。** 删除要做成一整组动作：断开连接、清本机登记、清最近记录、清上次设备、清封面文件、清方案草稿。当前只清了登记表，于是：设备还连着 → 固件不重新广播 → 扫描永远看不到它；「上次设备」没清 → 后台重连监控会在切页时自动连回去并把它写回列表。演示设备删掉后也不该下次启动自己回来，需要记住「用户显式删除过」。

**大卡电源键。** 三条路径都在静默返回：设备只有云端记录（没有本机连接标识）、连接中的几秒、连上但状态还没到。每一条都要有可见反馈。

**选灯效延迟。** 选中高亮本来点下去就变，但写设备完成后的读回会按设备真实状态重算选中项，一个迟到的读回把刚选的覆盖回去；写期间再点卡片则被静默丢弃。修法：选中在写入期间保持权威（迟到的读回丢弃）、写期间的点卡片排队而不是丢弃、只改单个分区时跳过预读与清空与回读（一次点击从十个来回降到一条命令）、成功后用刚发出的内容渲染不再额外读回。

不加 loading：这是客户端问题，不是硬件延迟。

## Acceptance criteria

- [ ] 删除当前连接的设备后它立刻从首页与「我的」列表消失
- [ ] 删除后重新扫描能搜到这台设备并重新添加
- [ ] 删掉的演示设备重启小程序不会自己回来
- [ ] 点仅云端记录设备的电源键，看到说明而不是毫无反应
- [ ] 点未连接设备的电源键，先看到「正在连接」再开关
- [ ] 连接失败时看到原因
- [ ] 点简单档效果卡，选中高亮在 100ms 内确定，不会被回滚
- [ ] 单分区灯组上连续快速点不同效果卡，每一次都被执行
- [ ] `npx vitest run`、`npx tsc --noEmit` 干净
- [ ] `node .auto/verify-deep.mjs` 通过
- [ ] 新增单测：删除的六处清理清单、写期间点击排队、单分区写入只发一条命令
