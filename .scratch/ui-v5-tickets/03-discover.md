## Parent

#85（规格：小程序 UI / 交互第五轮）

## What to build

把发现页重做成**清单式**，并把「扫描到设备」这一步从「点一下就跳走」改成「先填资料再添加」。

页面结构：灰底圆角搜索条、分组标题（「附近的设备」+ 台数）、每行一台设备（封面缩略图、名称、信号说明、四格信号条）、底部「重新扫描」文字按钮。没有设备时是空态文案，不是一条孤零零的灰条。

点任意一行 → 从底部升起**添加表单**：名称输入（预填优先级：已有备注 → 已有名称 → 广播名）、封面选择（相册，可选）、「添加并连接」主按钮。已添加过的设备预填现有资料，并有一行小字说明「已添加过，保存会更新本机资料」，避免把用户起过的名字覆盖掉。点遮罩关闭表单，扫描继续。

这张票同时确立两件后面会被复用的东西：页面内的底部弹层形态（不用系统动作面板，因为需要输入框与相册选图），以及名称与封面的写入路径（名称走设备备注并接既有云端同步旁路，封面走封面存储）。

## Acceptance criteria

- [ ] 发现页有灰底搜索条、分组标题、每行封面与信号条
- [ ] 搜索框能按名称过滤附近设备
- [ ] 点扫描结果弹出底部表单，不再直接跳转连接
- [ ] 表单预填名称；已添加过的设备带「已添加过」说明并预填原资料
- [ ] 填名称选封面后点「添加并连接」，设备被登记且首页显示新名称与新封面
- [ ] 点遮罩关闭表单且扫描继续
- [ ] 点遮罩后再次点同一行仍能正常打开表单
- [ ] `npx vitest run`、`npx tsc --noEmit` 干净
- [ ] `node .auto/verify-ui-interaction.mjs` 通过，并补「点结果弹表单而非跳转」
- [ ] 新增单测：弹层预填优先级、名称匹配规则、已添加判定
