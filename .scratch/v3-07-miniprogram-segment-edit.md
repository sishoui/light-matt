## 要构建什么

段编辑页：区间选择 + 两层灯效编辑 + blend 选择。这是"多灯效"在 UI 上真正落地的地方。

## 交互模型

```
进入段编辑(strip_id, seg_id?)
  → 从设备读该段当前值填草稿（新建时用默认值）
  → 用户编辑：
       区间 [start, end]（数字输入 + 灯珠位置示意）
       层 0：灯效类型 + 参数（不可为空）
       层 1：灯效类型 + 参数（可选，可为空）
       blend：覆盖 / 相乘 / 相加（仅两层时可选）
  → 点「应用」→ SetSegment → 等 ACK → QueryStrip 重读该带 → 用设备值覆盖草稿
  → 未应用就离开 → 丢弃草稿，不静默下发
```

## 范围

1. **区间选择**：数字输入 + 可视化条（每颗灯珠一格，高亮覆盖范围）。
   同带内已有段用不同颜色标出，重叠时实时提示。
2. **层编辑**：复刻 v2 的四类参数 UI（呼吸的周期/最暗/波形、彩虹的周期/跨度/方向、
   流光的周期/尾长/方向），但每个控件组可折叠，两层各一套。
3. **层 1 为空时 blend 控件禁用**（契约要求单层 blend 必须为 0）。
4. **客户端预校验**：周期下限（呼吸 334ms / 彩虹·流光 200ms）、区间合法性、
   空层 0——**在发请求前就拦下**，不要等问题回 `InvalidParam`。
5. **草稿与设备态的分离**：编辑态只在页面 `data` 里；「应用」成功后才更新会话镜像。
6. **删除段**：`ClearSegment` + 重读该带。

## 验收

- [ ] 新建段：选区 → 设层 0 → 应用 → 灯带对应区间变化，其余区间不变
- [ ] 双层：彩虹 + 呼吸相乘，肉眼可见明暗波动且颜色不畸变
- [ ] 三层尝试被阻止（UI 上只有两层入口）
- [ ] 重叠区间在提交前就有明确提示，不依赖设备报错
- [ ] 周期填 300ms 的呼吸在提交前被拦下并提示下限
- [ ] 单层时 blend 控件禁用；强行下发（测试注入）被设备回 `InvalidParam`
- [ ] 未应用就返回，设备状态不变
- [ ] 编辑第 3 条带的段，第 1、2 条带不受影响
