## 要构建什么

设备页 + 与后端的异步同步：本地优先的列表作为即时可用来源，后端负责跨设备同步。
登录可选，后端不可达不阻塞控制。

## 交互模型

```
启动 → 立即渲染本地设备列表（不等待网络）
     → 后台拉 GET /api/v1/devices 合并（按 hardwareId 去重，本地备注名优先）
     → 后端失败 → 保留本地列表，顶部提示「离线，仅显示本机记录」

设备页
├── 我的设备（本地 + 后端合并）
│    每项：名称（备注名 > 广播名）、灯带数、最近连接时间、连接按钮
└── 附近设备（实时扫描）
     与「我的设备」按 hardwareId 去重，已登记的标注「已知」
```

## 范围

1. **本地优先**：沿用 `device-history.ts` 的存储，改为以 `hardwareId` 为键（v2 用 deviceId/name）。
   上限从 8 提到 20。
2. **同步策略**：连接成功后异步 `POST /devices/:id/seen`；备注名改动先落本地再同步。
   **任何同步失败都不影响 BLE 控制**。
3. **身份提示**：`identityKind === "local"` 时在设备页顶部显示「仅本机可见」。
4. **设备详情页**：GPIO 表、每带灯珠数、固件版本、`hw_id`、自检按钮、改名、删除。
5. **切换设备**：断开当前连接 → 连新设备 → 重建会话（重新读 State 与各带配置）。
   必须清空上一台设备的段缓存，不能残留。

## 验收

- [ ] 断网启动，本地列表照常显示且能连接控制
- [ ] 连上设备后后端同步成功，列表里出现备注名
- [ ] 后端 500 / 超时，列表与控制完全不受影响，只有一次静默重试
- [ ] 3 台设备来回切换，段数据、灯带数、固件版本全部正确刷新，无残留
- [ ] 同一台设备在两台手机上各自看到不同的备注名（因为后端按 user 存）
- [ ] `identityKind: "local"` 时有明确提示
- [ ] 删除设备只解除关联，重新扫描仍能连上
