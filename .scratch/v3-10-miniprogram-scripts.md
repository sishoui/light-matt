## 要构建什么

剧本页：阶段时间轴 + 跨带预览 + 从设备读回。补齐 v2 里"能下发但读不回来"的缺口。

## 范围

1. **阶段时间轴**：每阶段一个卡片，显示时长、该阶段各带的段数摘要；
   支持改时长、删阶段、加阶段、调整顺序。
2. **fade 字段**：格式预留但 `caps.bit1 == 0`（当前固件未实现），
   **UI 不展示过渡选项**，只在数据里恒为 0。
3. **从设备读回**：`QueryScript(id)` 读摘要；需要完整内容时按阶段重读。
   v2 里 `queryScript` 存在但无 UI 绑定，这次要接上。
4. **下发流程**：复用现有 `script-plan.ts` 的编排（Begin→Stage×N→Segment×M→Commit），
   但段改为两层、`ScriptStage` 带 fade。
5. **容量预检**：下发前用 `protocol-v3.md` §10.4 的公式预估编码后大小，
   超 16384 字节**直接提示**「剧本过大，请减少阶段数/段数/灯带数」，不发请求。
6. **`ScriptTooLarge (0x0A)` 处理**：即使预检漏了，也要把设备返回的错误显示成人话，
   并明确"设备配置未改变"。
7. **播放控制**：play/pause/stop、loop，复用 v2 已有实现。
8. **跨带预览**：时间轴上能看出某阶段覆盖了哪几条带（不逐颗预览像素）。

## 验收

- [ ] 已提交的剧本断连重连后能从设备读回并显示
- [ ] 4 套剧本各自独立编辑、下发、激活，互不覆盖
- [ ] 构造超限剧本 → 下发前就提示，不发请求
- [ ] 强行下发超限剧本（绕过预检）→ 设备回 0x0A，界面明示且声明配置未变
- [ ] 阶段时长改 0 被拦下
- [ ] 播放/暂停/停止与 loop 行为正确，State 的 `stage_index` / `playback_state` 同步
- [ ] 剧本里的段是两层配置，激活后与直接设段的视觉一致
- [ ] 没有 fade UI 入口（caps 未实现时不暴露）
