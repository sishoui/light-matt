## 要构建什么

v3 的端到端真机验收，产出可复核的证据。

## 前置

所有实现票关闭，固件可烧录，小程序可真机预览。

## 验收项

### 功能

- [ ] **8 条灯带**：每条独立设不同颜色/灯效，互不干扰
- [ ] **每带开关**：关一条带其余继续跑动画；重开立刻恢复无残影
- [ ] **两层叠加**：彩虹 + 呼吸相乘能看出明暗波动且颜色不畸变
- [ ] **段不重叠**：划重叠被拒且提示明确
- [ ] **多阶段**：剧本下发 → 激活 → 播放 → 断连重连 → 从设备读回一致
- [ ] **剧本过大**：`ScriptCommit` 回 0x0A，界面明示且配置未变
- [ ] **多设备**：3 台设备来回切，无残留
- [ ] **断电恢复**：拔电重上，全局开关/亮度/每带开关/段配置/已提交剧本全部恢复

### 稳定性（沿用 #20 的方法）

- [ ] 8 带 × 64 灯 @20fps 连续 400s 录像，**错色率不高于 v2 基线 0.42%**
- [ ] 两层合成后单帧耗时实测，确认 20fps 撑得住（撑不住则记录降到多少 fps）
- [ ] 分片写（跨 2 片以上的命令）压力测试：连续 400s 下发，无重组失败
- [ ] 8 带全开 vs 只开 4 带的轮周期对比记录

### 文档

- [ ] `docs/protocol-v3.md` 标注"已实现"，`spec-v2.md` 标注作废
- [ ] `docs/agents/issue-tracker.md` 的票据表更新
- [ ] 验收证据（录像、日志、实测数字）归档

## 已知会丢失的数据（必须写进验收记录）

**v2 → v3 是断崖升级**：NVS 的 state blob v3 与 script blob v1 不被 v3 识别，
刷固件后全部回到默认值。个人测试阶段可接受，但要在验收记录里明确写明，
避免以后误判为 bug。
