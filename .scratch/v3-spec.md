## 目标

把 v2 已经做进固件、但小程序跟不上的能力补齐，并新增三样东西：**同段两层灯效叠加**、**每条灯带独立开关**、**设备登记**。

规格见 `docs/spec-v3.md`，字节契约见 `docs/protocol-v3.md`（含可执行向量 `docs/protocol-testvectors-v3.json`，由 `scripts/gen-protocol-testvectors-v3.mjs` 生成）。

## 变的是什么

| 能力 | v2 现状 | v3 |
|---|---|---|
| 8 条灯带 | 固件有，小程序 `PRIMARY_STRIP_ID=0` 写死 | App 全链路打通，灯带成为主界面切换维度 |
| 分段 | 只操作 strip 0 | 每带独立编辑 |
| 多灯效 | 一段一效 | **同段两层叠加 + 覆盖/相乘/相加** |
| 多阶段 | 下发可用、读不回来 | 读回、编辑、跨带预览 |
| 设备列表 | 弹层、本地 8 条 | 独立页 + 后端登记 |
| 每带开关 | 无 | 新增 `SetStripPower` |
| 引脚 | 编译期 Kconfig | **仍然只读**，新增 `QueryStripConfig` 供展示 |

## 协议 v3 要点

- 信封：`0xA6` / `0x03` / 16 位长度 / CRC16 + BLE 分片重组，逻辑帧上限 20B → **240B**
- 段：固定 **21 字节**，两层各 8 字节定宽（type + 7 参数）
- State：14B → **37B**，带每条灯带的灯珠数 / 段数 / 开关 / 动画位
- 新增命令：`SetStripPower 0x1B`、`QueryStripConfig 0x1C`、`QueryDeviceInfo 0x1D`
- 新增结果码 `0x0A ScriptTooLarge`：`ScriptCommit` 前预检持久化尺寸，**不再静默放弃**
- NVS：自定义分区表，24KB → 64KB；剧本 blob 上限 4KB → 16KB

## 关键取舍（不要"修复"）

- **不做运行期改引脚**：句柄热重建会放大已实测的 BLE 抢 RMT ISR 问题
- **不做每带独立亮度**：只有每带开关，亮度保持全局
- **最多两层**：三层以上段结构从 21B 涨到 29B，吃掉本就紧张的剧本容量
- **blend 只有三种**：不做取最大（与相加视觉重合）
- **fade_ms 只预留格式**：行为仍硬切
- **后端不存灯光配置**：设备 NVS 是唯一真相，双真相无解
- **不做设备归属访问控制**：个人测试阶段前提，只做登记展示

## 已知风险

1. 协议切换是断崖：v2 的 NVS blob 不兼容，刷固件后配置回默认值
2. 两层合成让每颗灯珠求值从 1 次变最多 2 次 + blend，需实测 20fps 帧预算
3. 最坏情况（8 带 × 8 阶段 × 8 段 × 两层动画）装不下 4 套剧本，用显式失败处理
4. 分片增加写次数，需复核错色率不高于 v2 基线 0.42%

## 执行顺序

A 协议契约（**已完成**）是所有实现票的闸门。之后固件侧与小程序侧可并行，后端完全独立。

```
A 契约 ✅
├── 固件协议层 → 固件两层引擎 → 固件剧本持久化 ┐
├── 小程序协议层 → 小程序拆页 → 灯光页/段编辑 ┤
└── 后端设备表                              ┴→ 端到端验收
```
