# 协议 v4 验收记录

**日期**：2026-11-03　**固件**：`feat/strip-editor-polish`（协议 `0x04`、固件号 `0x0400`）
**设备**：`CC:8D:A2:C2:56:62`（`Lumen-5662`），COM6
**探针**：`scripts/probe-v4.py`（真机，PC 当 central，需要 `bleak`）

结论：**协议层 22 项全部通过**。渲染观感类项目见文末「未覆盖」。

---

## 怎么复现

```bash
# 1. 编译并烧录（会重置设备配置）
scripts\build-firmware.cmd
scripts\flash-firmware.cmd COM6

# 2. 确认没有别的客户端连着它（开发者工具里的小程序、手机预览都会占住 BLE，
#    占住时设备不广播，探针会报 no-device）
# 3. 跑验收
python scripts/probe-v4.py
```

探针在结束时会把灯珠数、亮度、光区恢复成默认（`--skip-restore` 可跳过）。

> **为什么必须复位**：设备复位后约 6 秒就会被已配对的客户端重新连上，
> 届时不再广播，探针扫不到。脚本用 `capture-serial.py --reset` 制造广播窗口，
> 手工跑时请先断开所有客户端再上电。

## 3. 三种新灯效（#74）

| # | 项 | 期望 | 实测 | 结果 |
|---|---|---|---|---|
| 3.1 | 爆闪 `0x04`（250ms，duty 128） | 接受 | `0x00` | ✅ |
| 3.2 | 爆闪读回类型 | `0x04` | `0x04` | ✅ |
| 3.3 | 心跳 `0x05`（1000ms） | 接受 | `0x00` | ✅ |
| 3.4 | 心跳读回类型 | `0x05` | `0x05` | ✅ |
| 3.5 | 熄灭 `0x06`（参数全零） | 接受 | `0x00` | ✅ |
| 3.6 | 熄灭读回类型 | `0x06` | `0x06` | ✅ |

**参数规则（实测确认）**：熄灭要求 `hue / sat / p5 / period / flags` **全部为 0**；
给它一个非零色相会被拒（探针第一版就踩到，设备回 `0x01`，行为正确）。
`level` 不参与这条校验——熄灭本来就是黑的。

## 肉眼验收（2026-11-03，已确认）

以下五项由人眼确认观感正确：

1. **逐光区亮度的明暗对比** —— 同一条灯带上两个光区，`level` 100 / 25 的明暗差异肉眼可辨。
2. **呼吸谷底 = 光区亮度 × 最低亮百分比** —— 两个旋钮的语义不冲突。
3. **爆闪的节奏** —— 20fps 下仍能看出「闪」而不是「抖」。
4. **方案切换的可见变化** —— 切方案后灯上真的换了编排。
5. **清空方案后的熄灯行为** —— 删掉一套正在播的方案，灯不再按它跑。

## 仍建议补测（不阻塞）

- **8 × 100 灯珠的 TDM 满载时序**。上限从 64 抬到 100，每轮要推 800 颗；当前设备是
  30 颗/带，串口日志里 `tdm: strips=8 active=8 round≈7us` 是**空载**数字。
  接一条接近 100 颗的灯带后应该复看一次帧间隔与掉帧。
- **多光区编排下的长时间稳定性**。已有 v3 的 400s 压力数据，但那是 v3 配置；
  v4 多了 level 与三种新灯效、方案按需增长，值得再跑一次长压。
