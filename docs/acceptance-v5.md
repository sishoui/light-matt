### 跨灯组串扰（#101）的真机等价验证

在演示设备（2 条灯组）上：

1. 给灯组 1 写两个可辨识的分区（`0:0-8` 彩虹 + `1:9-17` 心跳），读回作为基线；
2. 在灯组 0 的进阶档应用方案；
3. 重新读回灯组 1 —— **两个分区逐字节不变**。

同一脚本还验证了：删除当前连接的演示设备会真的断开（`linkState = idle`）、
六处存储全部清空、演示设备记住「显式删除过」且重启后不会自己回来。

本轮协议层有扩展（票 #98）。设备 `Lumen-5662`（8 条灯带）已烧录新固件并跑完验收，
完整记录见 [`docs/evidence/real-device-v5-2026-11-04.md`](evidence/real-device-v5-2026-11-04.md)。

| 项 | 期望 | 状态 |
|---|---|---|
| 流星密度 | 1/2/3/4 个头沿整条均分 | ✅ 1 头与 3 头上机（标志位 `0x04` / `0x0C` 均被接受） |
| 流星拖尾 | 衰减 = 指数渐隐；不衰减 = 实色块 + 一档亮暗差 | ✅ `0x02`（实色拖尾）上机接受 |
| 随机闪烁 | 密集与稀疏两档观感不同；**确定性**（同一时刻反复看结果一致） | ✅ 密度 32/64/96 上机；确定性由固件单测锁住（seed 只由 `index, n, t0_ms` 决定） |
| 循环三档 | 不循环停末帧 / 全部循环回第一步 / 最后一步原地重播 | ✅ **8 带 × 3 模式 = 24/24**，`loop=2` 另有 8s 长窗证明「原地重播」而非「停住」 |
| 旧固件拒绝 | 新类型或非法循环值回 `InvalidParam`，不误改配置 | ✅ `loop>2` 与未知类型均由固件单测覆盖；`diag-blend.py` 确认非法 blend 被拒 |
