## 0. 已定的前提

- 灯效渲染在**固件**，小程序只下发「类型 + 参数」。
- 灯效建模 = **类型枚举 + 参数块**，不做设备端脚本。
- 首批四种：**静态单色、呼吸、彩虹、流光**；#74 追加**爆闪、心跳、熄灭**；
  #98 追加**随机闪烁**（`0x07`）并给流光加了头数量 / 实色拖尾，合计八种。
  **新类型的字节契约以 `docs/protocol-v4.md` §7.1 为准**，本文的公式仍适用于既有类型。
- 一条灯带最多 **8 段**；8 条灯带走 TDM 轮询。
- **逐段下发**，每帧一个段，帧 ≤ 20 字节（载荷 ≤ 14 字节）。
- 亮度上限 `max_brightness = 200`（State 第 7 字节报给小程序）。
- 亮度是**独立字段**，不折进 RGB；gamma 只存在于固件。

## 1. 设计决策（用户 2026-10-31 确认）

| # | 决策 | 取值 |
|---|---|---|
| D1 | 参数组织 | **每种灯效有专属参数块**，长度不同，帧载荷可变长 |
| D2 | 色相精度 | **2 字节**（0-65535，一整圈 ≈ 65536 级） |
| D3 | 速度单位 | **周期毫秒**，2 字节小端。`0` = 静止 |
| D4 | 流光跨段相位 | **每段独立相位**（跨段会断裂，接受） |
| D5 | 频率上限 | **呼吸 ≤ 3 Hz、彩虹/流光 ≤ 5 Hz** |
| D6 | 动画亮度 | **不额外降亮**。`max_brightness` 保持 200，动画与静态同上限 |
| D7 | 未知灯效类型 | **回 `InvalidParam`，不静默降级** |

### 采用可变长载荷的前提（已验证）

v1 信封的第 4 字节就是 `length`（载荷长度，0-14），`protocol.c` 的
`lumen_protocol_decode()` 已经按它校验并填充 `payload_len`。**所以可变长载荷不需要改信封结构**，
只需要 §5 的命令层按「类型 → 期望载荷长度」做二次校验。

### D1 的代价与收益

- **代价**：每种灯效的合法载荷长度不同，命令层要有「类型→长度」的映射表；小程序侧 codec 要为每种灯效单独编码。
- **收益**：呼吸可以有「最小亮度 + 波形」，流光可以有「尾部长度」，各自语义清晰，不用挤进一个通用字段。
- **不变**：信封、校验和、seq、ACK 语义全部沿用 v1，不受影响。

### D6 的后果（重要，必须记录）

**动画与静态共用 `max_brightness = 200`，动画不做额外限流。**

这意味着：

- 彩虹/流光可能让大量灯珠同时处于高亮，电流高于静态纯白的最坏情况（3.0A × 64 灯）。
- **8 条灯带时总电流还要 ×8**。
- 这是用户明确接受的取舍：**等实际测试时再决定要不要加限制**。

固件实现上**不要**偷偷加系数。若实测发现供电问题的判据是：整条变暗、闪断、`BROWNOUT` 复位、电源发热。届时再改 `max_brightness` 或加动画专用上限。

## 2. 参数块布局（按灯效专属）

所有多字节字段**小端**。`hue` 与 `sat` 是绝大多数灯效共有的前缀字段（熄灭除外，那里必须全 0），
但**参数块整体长度因类型而异**。

### 2.1 静态单色（type = 0x00）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | 色相 0-65535 |
| 2 | `sat` | 1 | 饱和度 0-255 |

**长度 3 字节。** 无周期、无 flags。

### 2.2 呼吸（type = 0x01）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | 色相 |
| 2 | `sat` | 1 | 饱和度 |
| 3-4 | `period_ms` | 2 | 完整呼吸周期，毫秒。**0 = 静止** |
| 5 | `min_level` | 1 | 最暗时的亮度占比 0-255 |
| 6 | `flags` | 1 | bit0 `reverse`（无实际意义，保留）；bit1-2 `waveform`；bit3-7 保留=0 |

**长度 7 字节。**

`waveform`：

| 值 | 波形 |
|---|---|
| 0 | 正弦 |
| 1 | 三角 |
| 2 | 锯齿 |
| 3 | 方波（两端各留 10% 线性斜坡，软起软落） |

### 2.3 彩虹（type = 0x02）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | 基准色相 |
| 2 | `sat` | 1 | 饱和度 |
| 3-4 | `period_ms` | 2 | 完整循环周期，毫秒。**0 = 静止** |
| 5 | `span` | 1 | 沿灯带的色相跨度：0 = 整条同色，255 = 铺满一整圈 |
| 6 | `flags` | 1 | bit0 `reverse`（色相递减）；bit1-7 保留=0 |

**长度 7 字节。**

### 2.4 流光（type = 0x03）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | 亮点色相 |
| 2 | `sat` | 1 | 饱和度 |
| 3-4 | `period_ms` | 2 | 亮点走完一趟的周期，毫秒。**0 = 静止** |
| 5 | `tail` | 1 | 尾部长度：0 = 硬边无尾，255 = 整条都是尾 |
| 6 | `flags` | 1 | bit0 `reverse`（反向移动）；bit1-7 保留=0 |

**长度 7 字节。**

### 2.5 爆闪（type = 0x04，#74）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | 色相 |
| 2 | `sat` | 1 | 饱和度 |
| 3-4 | `period_ms` | 2 | 一次完整闪烁的周期，毫秒。**0 = 静止（不出光）** |
| 5 | `duty` | 1 | 亮的时间占比 0-255：0 = 恒灭，255 = 几乎常亮；界面三档窄/中/宽 ≈ 40/90/153（≈15%/35%/60%） |
| 6 | `flags` | 1 | **必须为 0**（没有方向 / 波形位） |

**长度 7 字节**（复用呼吸/彩虹/流光的 7 字节块，层编码宽度不变）。

包络（方波 + 两端 5% 线性斜坡，避免硬切）：

```
phase = period_ms == 0 ? —（直接输出 0）
      : ((now - t0) mod period_ms) / period_ms      // 0..1
hi    = duty/255                                    // 高电平结束位置
p < 0.05          → phase/0.05                      // 上升沿 0→1
0.05 ≤ p < hi-0.05 → 1                              // 高电平
hi-0.05 ≤ p < hi  → (hi - phase)/0.05               // 下降沿 1→0
p ≥ hi            → 0                               // 低电平
RGB_i = hsvToRgb(hue, sat, 1.0) × e × (level/100)
```

**周期约束**：`period_ms` 下限 **100ms**（= 10Hz）。`duty` 全 0-255 合法；`duty = 0`
被实现为恒灭（不是「一个极窄的脉冲」）。`flags` 非 0 → `InvalidParam`。

> **频率上界的老实话**：固件默认 **20fps**（每帧 50ms），所以 10Hz 已经是能表现的上界——
> 一个 100ms 周期只有 2 帧。**本票（#74）不提高帧率**：8 条满 100 颗时提高帧率会掉帧，
> 那种掉帧比低频更糟。想要更快的爆闪，必须先解决 TDM 带宽（见 `Kconfig.projbuild` 的表）。

### 2.6 心跳（type = 0x05，#74）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | 色相 |
| 2 | `sat` | 1 | 饱和度 |
| 3-4 | `period_ms` | 2 | 一个完整节拍的周期，毫秒。**0 = 静止** |
| 5 | `pulse` | 1 | 单次脉冲宽度占比 0-255（界面固定中等 ≈ 60） |
| 6 | `flags` | 1 | bit0 双脉冲开关（默认 1）；bit1-7 保留=0 |

**长度 7 字节。**

包络（一个节拍内一大一小两次脉冲，其余时间谷底）：

```
phase = period_ms == 0 ? 0 : ((now - t0) mod period_ms) / period_ms   // 0..1
w     = max(pulse/255, 0.01)                                          // 单次脉冲宽，至少 1%
p < w             →  phase / w                                        // 脉冲 1：升到 1
w ≤ p < 2w        →  0                                                // 间歇（谷底）
2w ≤ p < 3w       →  (phase - 2w) / w × 0.6                           // 脉冲 2：升到 0.6（双脉冲开时）
p ≥ 3w            →  0                                                // 谷底
RGB_i = hsvToRgb(hue, sat, 1.0) × e × (level/100)
```

**周期约束**：`period_ms` 下限 **500ms、上限 1500ms**（= 40-120 BPM）。`flags` bit1-7
非 0 → `InvalidParam`。`double_pulse = false` 时第二次脉冲恒 0（单脉冲）。

> 这是「一大一小两次脉冲」的线性三角近似，不是心电图的精确形状。验收只看得到
> 两次幅度不同的脉冲（#74）。

### 2.7 熄灭（type = 0x06，#74）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0-1 | `hue` | 2 | **必须为 0** |
| 2 | `sat` | 1 | **必须为 0** |
| 3-4 | `period_ms` | 2 | **必须为 0** |
| 5 | `p5` | 1 | **必须为 0** |
| 6 | `flags` | 1 | **必须为 0** |

**长度 7 字节**（长度表与动画类一致，但语义上一个字节都不用）。

熄灭**永不发光**：像素函数直接返回全黑，不受 `level` 与时刻影响。它与「不画光区」
的区别是**在时间轴与光区轴上可见**，用户能明确表达「这一段就是黑的」。
`level` 不参与校验也不影响输出——熄灭本来就是黑的。

参数任一非 0 → `InvalidParam`（hue / sat / p5 的检查在
`lumen_segment_validate_shape`，flags / period 在 `lumen_segment_store_validate_params`）。

> **熄灭必须同时在 `lumen_effect_type_known` 与 `lumen_effect_type_implemented` 里为真**，
> 否则它作为 layer0 会被 §7.1 第 2 步拒绝（那条规则只认「已知且已实现」）。
>
> **熄灭不是动画类型**：`lumen_effect_is_animated(0x06)` 返回 false，否则一整组只有
> 熄灭的配置也会被拖进帧循环。实现上必须显式枚举，**不能**写成 `type != STATIC`。
>
> **熄灭作为叠加层（layer1）**：协议层不额外拒绝，语义就是「黑色叠加」——
> blend=覆盖时整段变黑，blend=相乘时结果也是黑。界面层不提供这个选项（叠加一个
> 熄灭等于什么都没做，只会让人困惑），但协议层不必为它写特例。

### 2.8 段配置整体载荷与长度汇总

段配置载荷 = **`strip_id(1) + seg_id(1) + start(1) + end(1) + type(1) + params`**

`strip_id` 标识这是第几条灯带（0-7，对应 8 引脚）。**没有它，8 条灯带的段无法区分**——已定（2026-10-31）。

| 类型 | 参数长度 | 载荷 | 整帧 = 6 + 载荷 | 余量 |
|---|---|---|---|---|
| 静态 0x00 | 3 | **8** | **14** | 6B |
| 呼吸 0x01 | 7 | **12** | **18** | **2B** |
| 彩虹 0x02 | 7 | **12** | **18** | **2B** |
| 流光 0x03 | 7 | **12** | **18** | **2B** |
| 爆闪 0x04 | 7 | **12** | **18** | **2B** |
| 心跳 0x05 | 7 | **12** | **18** | **2B** |
| 熄灭 0x06 | 7 | **12** | **18** | **2B** |

全部 ≤ 20 字节，**无需分包**。

> `start` / `end` 各 1 字节：`max_leds = 100`（#72 从 64 抬高），0-99 落在 0-255 内，够用。若要支持 >255 灯，改成 2 字节后动画类整帧正好 20 字节，**没有余量**——所以现在保持 1 字节。

> **⚠️ 动画类只剩 2 字节余量。** 这意味着给呼吸/彩虹/流光/爆闪/心跳**再加字段几乎不可能**（只剩 2 字节，且不能破坏现有布局）。若将来发现必须加，只能：
> ① 提高 `max_leds` 相关的 `start/end` 压缩（不可行，已是 1 字节下限）；
> ② 用 `flags` 的保留位（只剩 4-5 位）；
> ③ 升协议版本。
> **实现时不要假设有余量可以随便加字段。**
>
> **#74 的三种新类型没有吃掉这份余量**：爆闪 / 心跳 / 熄灭都复用现有 7 字节参数块，
> 没有扩宽层编码，所以载荷仍是 12 字节、整帧仍是 18 字节，协议版本号也不变。
> 这也是它们能塞进 v4 而不用升版本的原因。

> **`lumen_effect_param_len`**：静态 3；其余六种（呼吸 / 彩虹 / 流光 / 爆闪 / 心跳 / 熄灭）
> 一律 7；未知类型与空层 0。熄灭语义上只用 0 个字节，但长度仍报 7，
> 让两端只有一张长度表（剧本 blob 的记录宽度也因此保持 5/9/13/21 不变）。

## 3. 行为公式

约定：

- `t` = 该段本地时间（秒，从该段**配置生效**那刻起算）。
- `period_ms = 0` 时所有动画静止（`phase = 0`），效果等同于冻结在当前相位。
- `rate_freq = 1000 / period_ms`（Hz）。
- 色相转 RGB 用 `hsvToRgb(hue_deg, sat/255, 1.0)`，**V 恒为 1**，之后 `lumen_gamma_apply(channel, brightness)`。
- 所有运算走 **32 位整数**，不用 `float`（C3 无 FPU；`gamma.c` 只在初始化时用 `math.h` 建表，运行时查表，没问题）。

### 3.1 静态单色

```
每颗灯：hsvToRgb(hue, sat, 1.0)
```

### 3.2 呼吸

```
period_s = period_ms / 1000
phase    = period_ms == 0 ? 0 : (t mod period_s) / period_s      // 0..1
e       = 包络(phase, waveform)                                  // 0..1
e'      = min_level/255 + (1 - min_level/255) × e                // 叠加最暗基线
RGB_i   = hsvToRgb(hue, sat, 1.0) × e'
```

包络定义：

| 波形 | e |
|---|---|
| 正弦 | `0.5 × (1 - cos(2π × phase))` |
| 三角 | `1 - abs(2 × phase - 1)` |
| 锯齿 | `phase` |
| 方波 | `phase < 0.5 ? 1 : 0`，但首尾各 10% 做线性过渡 |

### 3.3 彩虹

```
phase   = period_ms == 0 ? 0 : (t mod period_s) / period_s
N       = 该段灯珠数
hue_i   = hue + (phase × 65536) + (i / N) × (span / 255) × 65536 × dir
         （dir = reverse ? -1 : 1，结果对 65536 取模）
每颗灯：hsvToRgb(hue_i, sat, 1.0)
```

- `span = 0` → 整条同色，色相随时间循环。
- `span = 255` → 沿灯带铺满一整圈，随时间平移。

### 3.4 流光

```
phase   = period_ms == 0 ? 0 : (t mod period_s) / period_s
N       = 该段灯珠数
tail_n  = 1 + (tail / 255) × (N - 1)        // 尾部覆盖的灯珠数（1..N）
p_i     = ((i / N) - phase) mod 1           // 亮点经过 i 时为 0
w_i     = p_i < tail_n / N
            ? exp(-(p_i × N / tail_n) × 3)  // 指数衰减，常数 3
            : 0
RGB_i   = hsvToRgb(hue, sat, 1.0) × w_i
```

- `reverse` 反转移动方向。
- **每段独立相位**（D4）：`t` 从该段配置生效起算，跨段不连续。

## 4. 与分段、gamma、亮度、电流的交互

### 4.1 分段

> **重叠规则以 [`protocol.md`](./protocol.md) §10.3 为准：重叠时被拒绝（`InvalidParam`），不是覆盖。**

- 每段独立持有：`type + 参数 + 灯珠区间 + 生效时间戳`。
- 段之间相位独立（D4）。
- **未被任何段覆盖的灯珠必须写 0（熄灭）**。WS2812B 会锁存，不主动清零就一直亮着——这是避免残影的必要条件。
- 段区间不能重叠；重叠时后下发者覆盖（并在 ACK 里保持 OK，因为逐段下发无法做全局原子校验）。

### 4.2 gamma 与亮度

- 灯效算出的是**用户空间 RGB（0-255）**。
- **最终输出 = `lumen_gamma_apply(rgb_channel, brightness)`**，与 MVP 一致。
- 亮度滑块与灯效亮度**相乘叠加**：动画包络改用户空间值，滑块再统一缩放。这样拖亮度不破坏灯效的相对关系。

### 4.3 电流预算（D6：本期不处理）

- **动画与静态共用 `max_brightness = 200`，不加额外系数。**
- 风险已知并接受：彩虹/流光可能让大量灯珠同时高亮；8 条灯带时总电流 ×8。
- **等实测再定。** 判据：整条变暗 / 闪断 / `BROWNOUT` 复位 / 电源发热。
- **固件实现禁止偷偷加限流系数**——若加了，实测数据就失去意义。

## 5. 校验规则（设备侧）

按顺序检查，任一失败回对应错误码，**整帧不生效**：

| 顺序 | 检查 | 条件 | 结果 |
|---|---|---|---|
| 1 | 信封 | magic/version/length/checksum | 沿用 v1 规则 |
| 2 | 类型已知 | `type ∈ {0x00,0x01,0x02,0x03,0x04,0x05,0x06}` 且本固件已实现 | 否则 `InvalidParam`（D7） |
| 3 | 载荷长度匹配类型 | 见 §2.8 的期望长度 | 否则 `BadLength` |
| 4 | 段区间 | `start ≤ end`，且 `end < led_count` | 否则 `InvalidParam` |
| 5 | flags 保留位 | 静态/爆闪 `flags == 0`；呼吸 bit3-7、彩虹/流光/心跳 bit1-7、熄灭全部 == 0 | 否则 `InvalidParam` |
| 6 | 周期区间 | 呼吸：`period_ms != 0` 时 `≥ 334`（≈3Hz）<br>彩虹/流光：`!= 0` 时 `≥ 200`（5Hz）<br>爆闪：`!= 0` 时 `≥ 100`（10Hz）<br>心跳：`!= 0` 时 `500-1500`（40-120 BPM）<br>熄灭：`period_ms == 0` | 否则 `InvalidParam` |
| 7 | 熄灭参数 | 熄灭层的 `hue / sat / p5 / flags / period_ms` 全为 0 | 否则 `InvalidParam` |

### 为什么周期下限是 334 / 200 / 100 与心跳上下限 500-1500

- 呼吸 ≤ 3 Hz → `period ≥ 1000/3 = 333.3ms`，取 **334** 保证不超 3 Hz。
- 彩虹/流光 ≤ 5 Hz → `period ≥ 200ms`。
- 爆闪 ≤ 10 Hz → `period ≥ 100ms`。这是**固件能表现的上界**（默认 20fps，每帧 50ms），
  不是安全线；本票不提高帧率（理由见 §2.5）。
- 心跳 40-120 BPM → **500-1500ms**。低于 500ms 会快成心跳过速的一次「抖」，
  高于 1500ms 已经不像心跳而像两次孤立的闪。
- 3 Hz 是亮度闪烁的光敏性癫痫安全线；流光 5 Hz 是**空间移动**而非亮度闪烁，相对安全，所以放宽。

### 为什么未知类型不降级（D7）

静默降级会让用户以为设置成功但效果不对，比明确报错更难排查。未来新增灯效时，旧固件回 `InvalidParam`，小程序据此提示「该灯效需要升级固件」。

## 6. 固件实现要点（给 #22 的输入）

- **整数运算**：色相、相位、包络全部 `int32/uint32` 定点。`exp` 用查表或分段线性近似，不要调 `expf`。
- **每段状态**：`{ uint16_t hue; uint8_t sat; uint16_t period_ms; uint8_t p5; uint8_t flags; uint8_t type; uint8_t start, end; uint32_t t0_ms; }` ≈ 15 字节。
  8 段 ≈ 120 字节；8 条灯带 × 8 段 ≈ 960 字节，RAM 可接受（当前空闲 heap 316KB）。
- **相位计算**（单位已核对，且避开了溢出边界）：
  ```
  uint32_t r = (now_ms - t0_ms) % period_ms;   // 无符号减法，先取模
  uint32_t phase_q16 = (uint32_t)(((uint64_t)r << 16) / period_ms);
  ```
  **必须用 `uint64_t` 中间量。** `period_ms` 最大 65535 时 `r<<16` 最大为 `65534 × 65536 = 4294836224`，
  距 `2^32 = 4294967296` 只剩 **131072 的余量**——任何 `+1` 之类的偏差都会翻车。用 64 位中间量是零成本的保险，
  不要在 32 位里抠这几个字节。
- **`elapsed_ms` 回绕**：`esp_timer_get_time()/1000` 约 49 天回绕。因为先 `mod period_ms`，且 `period_ms ≤ 65535`，回绕不影响相位；但**必须用无符号减法** `now - t0`，否则跨零会得到负数再被转成巨大的正数。
- **未知/非法帧不改像素**：保持上一帧，避免闪黑。
