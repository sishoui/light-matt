> 固件侧已经证明的：命令能收到（`RX cmd=0x01 ... changed`）、状态能写入、渲染任务能执行

>
> 排查顺序见 §0.2.1。灯带点亮之后，才能判定颜色顺序与供电边界。

#### 0.2.1 灯带不亮时的排查顺序

1. **共地**：开发板 GND 与灯带电源 GND 必须直连。这是最常见的失败原因。
2. **灯带供电**：灯带 5V 是否独立供电（不要只靠开发板 USB 5V 带 30 灯）。
3. **DIN 接对**：灯带数据线必须接 **GPIO3**（不是 D4、不是别的丝印）；接的是 DIN 端不是 DOUT 端。
4. **方向**：灯带箭头指向远离开发板，DIN 在首灯。
5. **用 bring-up 固件单独验证**：`scripts\build-led-bringup.cmd` + `scripts\flash-led-bringup.cmd COM6`，
   它不依赖 BLE，开机就跑 红→绿→蓝→暖白→全白。
   - bring-up 也亮 → 接线没问题，回来查 BLE 路径（但当前日志已排除软件层）
   - bring-up 也不亮 → 纯硬件问题，回到第 1–4 步

### 0.3 烧录与启动

```bat
scripts\build-firmware.cmd
scripts\flash-firmware.cmd COM6
```

串口应出现：

```
lumen_ble: GATT 服务已注册（Service 6c756d65-...-0001，RX/TX/State）
lumen_ble: 开始广播（Lumen-XXXX），等连接
lumen_app: 初始化完成：NVS → state_store → led_engine → ble_link
```

> 需要看原始帧字节时，把日志级别调到 DEBUG
> （`idf.py menuconfig` → Component config → Log output → Default log verbosity → Debug）。
> 产品路径每帧只打一行 RX 汇总，这是为了不让串口本身拖慢 20Hz 写入。

### ⑤ 断线后自动回连并恢复 UI 状态

**操作**：给设备断电，等 10 秒，再上电。

**应观察到**：

## 2. RMT × BLE 共存（前置门禁）

按 [#7 实验方案](./rmt-ble-stability.md) 跑五组实验。**判定线**：30 分钟高频写入下
错色 ≤ 1 次/10 分钟且用户不可感知。

若判定**不可接受**，第 ①–⑦ 条验收没有意义——需要先评估 SPI 驱动 WS2812 的备选路线
（方案见 `rmt-ble-stability.md` §8）。

| 组 | 配置 | 时长 | 错色次数 | 结论 |
|---|---|---|---|---|
| 1 BLE 未连接基线 | `48 steady sync 30` | 30 min | | |

| 4 `mem_block_symbols` | 48 / 96 / 192（384 预期失败） | 各 10 min | | |
