# 灯效修复的真机与模拟验收（2026-11-06）

- **设备**：`Lumen-5662` @ `CC:8D:A2:C2:56:62`，固件本轮重编并烧录（COM6），**8 条带 × 30 颗**
- **分支**：`fix/no-segment-black-and-layer-blend`
- **规格**：用户现场报告的四个现象——「所有引脚默认亮黄 / 改一组全变红 / 调饱和度全体跟着变 / 覆盖层看不见彩虹」
- **产物**：[`.sim-out/`](../../.sim-out)（模拟出图）、`scripts/probe-layer-fixes.py`（真机探针）

---

## 1. 修了什么

| 现象 | 根因 | 修法 |
|---|---|---|
| 所有引脚默认亮黄 | `led_render.c::compose_frame` 在零活动段时**整条铺 `state->r/g/b`**（默认暖白 255,180,120，WS2812B 上看是黄） | 删掉单色回退：零分区一律全黑（§9.3 第 2 条） |
| 改一组全变红 | `state_summary_apply` 把 strip0/seg0 层0 的 hue+sat 反算进 State，渲染层又拿它铺满**所有**无分区的带 | 同上；同时 `seg_count == 0` 时 R/G/B 报 `0,0,0` |
| 调饱和度全体跟着变 | 同上——「饱和度」实际在调那个全局兜底色 | 同上 |
| 覆盖层看不见彩虹 | 两层叠加默认 `blend = 0x00`（覆盖），流星的黑像素整片盖掉背景 | 新增 `blend = 0x03`「按亮度叠加」，界面唯一的叠加方式 |

`0x03` 的定义（契约 §7.2.1）：`a = max(L1)/255`，`out = L1 + L0 × (1 − a)`。上层亮处
显上层、暗处透出下层。取三通道**最大值**而不是平均值——单色流星只有红通道非 0，取平均
会让它永远半透明。

## 2. 真机探针（`scripts/probe-layer-fixes.py`）

```
===== 8 passed / 0 failed =====
```

| 检查项 | 结果 | 实测 |
|---|---|---|
| strip 0 有 1 个分区、其余 7 条为 0 | ✅ | `seg_counts=[1,0,0,0,0,0,0,0]` |
| 有分区时 State R/G/B = 该分区颜色 | ✅ | `rgb=255,0,0`（设为纯红） |
| 零分区时 seg_count = 0 | ✅ | `seg_counts=[0,0,0,0,0,0,0,0]` |
| **零分区时 State R/G/B = 0,0,0** | ✅ | `rgb=0,0,0` |
| `blend=0x03` 被接受 | ✅ | `result=0x00` |
| `blend=0x03` 读回 | ✅ | `blends=['0x3']` |
| `blend=0x04` 仍被拒 | ✅ | `result=0x01 InvalidParam` |

**断电重启后仍是 `rgb=0,0,0`**：串口 `state restored: power=1 brightness=128 rgb=0,0,0
leds=30 segs=0`，且没有 `render:` 单色行——证明归零已落盘，且没有走回退路径。

原有的 43 项协议行为**零回归**（`probe-v4.py`：43 passed / 0 failed）。

## 3. 模拟验收（`scripts/simulate-strips.py`）

宿主上直接编译并运行固件真实的 `effects.c` / `segment_store.c` / `gamma.c` /
`led_render.c`，只把「刷 RMT」换成留在内存里。像素与真机逐字节同源。

```
===== 32 passed / 0 failed =====
```

| 场景 | 关键结果 |
|---|---|
| `zero-zones` | 8 条全部 `(0,0,0)` |
| `only-strip0` | strip 0 是彩虹，strip 1–7 逐颗 `(0,0,0)` |
| `only-strip0-hue` | 换色后 strip 1–7 **逐字节不变** |
| `luma-blend` | 峰值 165，1 颗近白亮处、28 颗彩色、0 颗黑点；8 帧画面各不同 |
| `over-blend`（对照） | 黑 22 / 彩 0——背景被完全吃掉 |
| `luma-on-solid` | 近白 1 颗，背景蓝 29 颗 |

**逐颗数值证据**（`luma-blend`，`t=0ms`）：

```
[165,165,165]  ← 流星头（近白）
[165,129,122]  ← 尾巴渐隐，红通道保留
[165,117, 90]
[165,120, 68]
[165,137, 51]
[165,165, 39]  ← 已完全回到彩虹
```

对照 `over-blend` 同一配置：整条带只剩灰白渐隐 + 漆黑，彩虹消失。

### 未验证

- **渲染回归（`ui` 层）**：微信开发者工具自动化端口没开（9501/9502 均拒连）。
- **WS2812B 色域压缩 / 电源压降 / RMT 时序**：模拟器按定义覆盖不到，仍需真机。
- **摄像头取证**：本轮放弃。实测只点亮 strip 0 时画面里只有一个小光点
  （`.layout-shots/layout-0.png`），机位拍不到灯带本体；用拍不到灯的设备做验收只会
  得到噪声。改由模拟器承担「看效果」这一环。

## 5. 与用户描述逐条对照

| 用户原话 | 现在 |
|---|---|
| 「所有引脚灯效都显示未设置，但实际都显示黄色」 | 无分区 = 全黑；界面显示「空」而不是「未设置」 |
| 「默认状态应该是空，而不是未设置」 | 灯效行与设备页卡片都写「空」 |
| 「修改一个引脚为彩虹时，其余引脚变成红色」 | 其余带逐字节 `(0,0,0)`（模拟与真机探针双双验证） |
| 「调整彩虹饱和度时，所有引脚饱和度都跟着变化」 | 跨场景比对：改 strip 0 后 strip 1–7 逐字节不变 |
| 「背景层彩虹 + 覆盖层流星，看不见彩虹」 | `0x03` 下暗处保留彩虹，只有流星亮处被覆盖 |
| 「覆盖逻辑应是有流星灯的灯珠显示流星，其余显示彩虹」 | 正是 `0x03` 的定义 |
| 「背景层和特效层分成两个卡片，配置项与简单灯效一致」 | 两张独立卡片，共用同一张 wxml 模板与同一套 `SLIDER_KEYS`/`CHOICE_KEYS` |
