## 1. 循环三档（8 条灯带 × 3 种模式 = 24 组）

`.scratch/ble-test/test-8pins.py` → `8pins-results.json`：**24 / 24 通过**。

每条灯带一套独立剧本（3 阶段 / 多分区 / 双层且混合方式各不相同，只用自己那条带），
三种循环各跑一次：

| 模式 | 判据 | 实测 |
|---|---|---|
| `loop=0` 不循环 | 序列 `[0,1,2]`，停在 stage2 且 `playback=0` | 8/8 通过 |
| `loop=1` 全部循环 | 序列含 `[0,1,2]` 且之后回到 0 | 8/8 通过 |
| `loop=2` 最后一步循环 | stage 恒 2、`playback` 恒 1、`flags` bit0+bit2 置位（`0x07`） | 8/8 通过 |

每次采样都核对**其它 7 条带的 `seg_counts` 全为 0**——不串扰。

### `loop=2` 的「原地重播」单独证明

State 里读不到 `elapsed_ms`，所以用**长观察窗**证伪「跑完停住」：
最后一步 1200ms，观察 8 秒（约 6–7 轮），判据是 `playback` 始终为 1、`stage` 始终为 2。
对照组 `loop=0` 在同样窗口内 `playback` 归 0。脚本：`verify-loop2-replay.py`。

## 2. 流星：密度与拖尾（标志位）

`test-8pins.py` 里用到了三组标志位组合，覆盖 1 / 3 个头与实色拖尾：

| flags | 含义 | 用在哪条带 |
|---|---|---|
| `0x04` | 密度 = 1 个头（`(0x04>>2)=1` → 1 头） | strip 3 / 6 |
| `0x0C` | 密度 = 3 个头 | strip 0 / 3 / 7 |
| `0x02` | 实色拖尾（`LUMEN_COMET_FLAG_SOLID_TAIL`） | strip 0 |

全部被设备接受（ACK 0）且剧本提交成功，说明标志位的**保留位校验已按 #98 收窄**
（旧固件会把 `0x04` / `0x0C` 当非法保留位拒绝）。

## 3. 随机闪烁（0x07）

`test-8pins.py` 在 strip 2 / 4 / 5 / 6 上放了 `FLICKER`（含单层与叠加两种用法），
剧本提交与播放均正常。密度用 `p5` 给了 32 / 64 / 96 三档。

> **确定性**这一项（同一颗灯珠同一时刻结果一致）由**固件 host 单测**证明
> （`lumen_effect_flicker_gain_q16` 的 seed 只由 `(index, n, t0_ms)` 决定，
> 不含 `now_ms`），真机上无法用 State 读出单颗灯珠的瞬时亮度。
