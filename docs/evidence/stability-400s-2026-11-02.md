## 2. 判定不是空转（为什么 0 事件可信）

0 事件最容易是「什么都没在判」。本轮逐帧复核了参与度：

```
帧数 2215；可判定带×帧 = 11075；其中判 dark 的 0 次，NaN 色相 0 次
```

即每一帧都对 strip 0/4/5/6/7 做了 `LIT_MIN → dim/bright → wrong_hue` 四项检查，
11075 次机会里 0 次触发。这不是「判定器没跑」。

各带基线噪声（p95，取自配对基线前 120 帧）：

| strip | 基线色相 | 强度 | 噪声 |
|---|---|---|---|

| 2 | 159.8° | 67.3 | 11.2°（排除） |

## 3. 方法论证据：跨会话复用基线会刷满假事件

同一台设备、同一套固件、同一份标定，第一次跑（`.runs/v3/stress-400.*`）
配的是**上一次会话**录的基线，判定报：

```
事件数 58    折算 87.02 次/10 分钟    判据：未通过
kinds: {'wrong_hue': 58}    全部落在 strip 7
```

逐帧复核发现这不是固件异常：

| 检查 | 结果 |
|---|---|
| strip 7 在压力段内相对**自己中位数**的偏离 | p50 1.4°、p90 4.2°、p99 7.8°、max 13.6°；**>28° 的帧 0 个** |
| strip 7 压力段色相中位数 | 293.5°（std 2.5°，极稳） |
| strip 7 基线色相中位数 | 268.7°（std 2.6°） |
| 两者差 | **24.8°** —— 恒定偏移，不是抖动 |

再横向看 7 条带的两轮对比：

| strip | 基线色相 | 压力段色相 | Δ | 基线强度 | 压力段强度 |
|---|---|---|---|---|---|
| 0 | 338.3° | 302.6° | **35.7°** | 100.0 | 160.8 |
| 2 | 171.4° | 165.8° | 5.6° | 68.3 | 79.2 |
| 3 | 185.3° | 192.5° | 7.2° | 99.1 | 126.6 |
| 4 | 244.7° | 243.8° | 0.9° | 187.4 | 195.1 |
| 5 | 245.7° | 241.9° | 3.8° | 179.3 | 192.1 |
| 6 | 242.3° | 242.4° | 0.1° | 181.1 | 191.7 |
| 7 | 268.7° | 293.5° | 24.8° | 128.8 | 159.2 |

**每条带的亮度都涨了**（+12%~+60%），色相按位置偏移不同（0.1°~35.7°）。
这是**整幅画面的照明/白平衡漂移**，与 TDM 串带（会表现为某条跳到另一条的
颜色、且伴随亮度异常）形态不同。8 个固件色相里有 4 条（4/5/6/2）
在两次录制间几乎不动，说明固件输出没变。

同一次录制内部再看基线的前 60 帧 vs 其余帧：偏移 ≤2.3°、强度 ≤0.2 ——
**会话内极稳，会话间漂移**。这就把「基线必须紧邻压力段录制」从文档警告
变成可复现的反例。

处置：重录一次「基线 → 紧接压力段」，即 `stress-400b`，结果 0 事件。

## 4. 仍然存在的限制（不是本轮能解决的）

1. **只判定 5/8 条带。** strip 1 物理上只有 2 颗灯（几何定不出方向）；
   strip 2/3 采样点落在光晕上，基线噪声超门限。
2. **`crosstalk`（串带检测）在这台相机上不可用。** 参考色相最近只差
   0.7~1.1°，低于 28° 判定门限，工具已自动禁用。所以「TDM 串带」这个
   **内容级错误类型本轮无法回答** —— 这是 `pending-tasks.md` §3 的最大阻塞，
   本轮没有改变它。
3. **1080p 只有 5.5fps**，固件 20fps，抽样率约 27%。短于一帧间隔的瞬态抓不到。
4. **400s 里没有一次掉电 / 复位**，所以本项只覆盖「连续播放 + BLE 压力」，
   不覆盖「重启后恢复」—— 后者由 §1.8 覆盖。

## 5. 复现

```bash
# 1) 配置 8 带专属色相（改设备状态）
python scripts/ble-stress.py --brightness 60 colorize

# 2) 基线：必须紧邻压力段，不要跨会话复用
python scripts/record-board.py .runs/v3/base.mp4 --seconds 40 \
       --width 1920 --height 1080 --exposure -11

# 3) 压力段（另开一个终端先起 flood，再立刻录像）
python scripts/ble-stress.py flood --seconds 410 --hz 20 --brightness 60
python scripts/record-board.py .runs/v3/stress.mp4 --seconds 400 \
       --width 1920 --height 1080 --exposure -11

# 4) 判定（--reference 必须给，否则会用待测录像自己的前 N 帧当基线）
python scripts/analyze-strips-video.py .runs/v3/stress.mp4 \
       --reference .runs/v3/base.mp4 --json .runs/v3/stress-analysis.json
```

**机位、曝光、分辨率任一改变都要重跑 `strip-layout.py --isolate` 重新标定。**
