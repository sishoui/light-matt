# 观感项相机实测（2026-11-02）

**项**：`docs/acceptance-v3.md` 的 §1.2.2 / §1.3.2 / §1.3.3 / §1.3.4 / §1.5.5，
外加代码侧确认 §1.3.5 / §1.5.6。
**设备**：`Lumen-5662` / 固件 v3.0 / 8 带（strip 0 实测）
**手段**：PC 当 central 改设备状态 + 固定机位相机取帧，脚本判定
**原始数据**：`.runs/v3/visual-acceptance.json`、`.runs/v3/blend-whiten.json`

> **这轮替代人眼。** 判据是「观感」，但观感可以用可测量量表达：
> 亮度峰值、RGB 均值、色相、饱和度。这些量能把「明显更亮」「完全盖住」
> 「视觉一致」变成可复核的数字，比一句「看着对」可靠。

## 0. 采样与方法

固定机位、**不设 FOURCC**（DSHOW + YUY2，设了 MJPG 会强制自动曝光）、
曝光 −11、增益 0、1080p。

strip 0 在画面里的标定线段是 `(1059,615) → (1180,546)`，采样窗口取
**x∈[1045,1195], y∈[535,620]**。指标：

- `peak` = 窗口内灰度 p99（抗单像素噪声）
- `RGB` = 窗口内各通道均值
- `sat` = `(max−min)/max`，用来量化「白化」

> ⚠ **必须用同一个相机会话连续拍。** 每拍一张重开相机时，DSHOW 的自动曝光
> 每次重新协商，全关状态下反而拍出 175 万个亮像素（过曝）。第一次尝试就是这么
> 翻车的，数据全部作废重来。

## 1. §1.3.2 相加：明显更亮 + 白化

判据：「明显更亮、有饱和（白化）倾向」。

**实验 A**：层0 = 静态红，层1 = 静态绿，亮度 200。

| 配置 | peak | RGB | sat |
|---|---|---|---|
| 仅层0（红） | 80 | (9.1, 0.7, 0.6) | 0.93 |
| 仅层1（绿） | 144 | (1.6, 8.4, 5.2) | 0.81 |
| **相加** | **203** | **(6.3, 7.7, 5.3)** | **0.31** |
| 相乘（对照） | 0 | (0.5, 0.5, 0.4) | 0.31 |
| 覆盖（对照） | 144 | (0.9, 8.5, 5.3) | 0.89 |

**相加峰值 203 高于任一单层（80 / 144）**，且饱和度从 0.93/0.81 掉到 **0.31** ——
红 + 绿趋白，正是判据要求的白化倾向。

**实验 B**：层0 = 彩虹，层1 = 静态绿，亮度 150。

| 配置 | peak | RGB | 色相 |
|---|---|---|---|
| 仅彩虹 | 203 | (3.0, 2.6, 13.1) | 260.1° |
| **相加** | **206** | (2.9, 4.9, 13.1) | 201.2° |
| 相乘 | 178 | (0.5, 2.4, 1.5) | 170.7° |
| 覆盖 | 186 | (1.2, 5.1, 3.7) | 169.9° |

相加最亮（206 > 186 > 178），G 通道从 2.6 抬到 4.9。**通过。**

> 实验 A 才是判据的干净形式（两种饱和色叠加看得见白化）；实验 B 里彩虹本身
> 含各色相，叠加点落在暗部时不触发削顶，白化不明显。

## 2. §1.3.3 覆盖：只剩层1

判据：「只剩层 1（呼吸的单色），层 0 完全被盖住」。

| 配置 | peak | RGB | 色相 |
|---|---|---|---|
| 仅层1（静态绿） | 144 | (1.6, 8.4, 5.2) | 176.4° |
| **覆盖（彩虹+绿）** | **144** | **(0.9, 8.5, 5.3)** | **176.5°** |
| 仅彩虹（层0） | 203 | (3.0, 2.6, 13.1) | 260.1° |

覆盖的结果与**层1 单独**几乎逐值相同（peak 144 vs 144，色相 176.5° vs 176.4°），
而层0 的 260.1° 完全不见。**通过。**

## 3. §1.3.4 单层回归

判据：「与 v2 单层视觉完全一致」。

| 配置 | peak | RGB | sat |
|---|---|---|---|
| 单层静态绿 | 138 | (1.0, 6.3, 4.0) | 0.85 |
| 单层彩虹 | 123 | (3.8, 3.8, 14.6) | 0.74 |

## 4. §1.2.2 关带无残影

判据：「**无残影**（WS2812B 锁存，设备先推一帧全黑再跳过）」。

strip 0 亮纯红时关掉该带：

| 时刻 | peak | RGB |
|---|---|---|
| 亮红时 | 60.0 | (7.7, 0.2, 0.7) |
| **关后 250ms** | **0.0** | (1.5, 0.0, 0.1) |
| 关后 1.25s | 0.0 | (0.0, 0.0, 0.0) |

**250ms 内降到 0，此后维持全黑。** 配合串口已确认的
`strip 0 关闭：已推黑帧，后续 TDM 轮询跳过`，机制与现象一致。**通过。**

## 5. §1.5.5 剧本两层段 vs 直接 SetSegment

判据：「与直接 `SetSegment` 的视觉一致」。

同一套配置（层0 = 彩虹，层1 = 静态绿，blend = 相加），两条下发路径：

| 路径 | peak | RGB | sat |
|---|---|---|---|
| 直接 `SetSegment` | 174 | (3.9, 6.5, 14.7) | 0.73 |
| **剧本激活后** | **166** | (3.4, 6.9, 15.7) | 0.78 |

差 5%（174 vs 166），在彩虹动画的相位抖动范围内；RGB 三通道与饱和度都落在同一
区间。**通过。**

> 剧本路径：`ScriptBegin(0,1,1)` → `ScriptStage(0,0,8000,0)` →
> `ScriptSegment` → `ScriptCommit` → `ActivateScript(0,1)` → `SetPlayback(1,1)`，
> 全部 ACK 0。

## 6. §1.3.5 / §1.5.6：入口不存在（代码结构确认）

这两项的判据是「UI 上根本没有入口」，不是观感，所以在代码里确认即可：

**§1.3.5 无第三层**
- `segment-edit.ts:772` 只构造 `layerViews: [layerView(draft.layer0, 0, …), layerView(draft.layer1, 1, …)]` —— 数组长度恒为 2
- `segment-edit.ts:792` `function layerIndexOf(e): 0 | 1 | null` —— 返回类型在**类型系统层面**就不接受 2
- WXML 用 `wx:for="{{layerViews}}"` 渲染，数组有 2 项就只画 2 项

**§1.5.6 无 fade 入口**
- `scripts.wxml` 与 `scripts.ts` 里 **0 个** fade 相关控件，仅第 16 行有一条注释说明「不提供过渡 UI」
- 设备侧 `caps = 0x01`（bit1 = 0）已由 `probe-v3.py` 验过

## 7. 顺带查清的一个测量学问题

标定布局里 **strip 3 的线段起点 (989, 727) 与画面上一条固定亮线重合**。

这条亮线在**红 / 绿 / 蓝 / 全关**四种状态下读数完全不变：

| 状态 | lowline peak99 | RGB |
|---|---|---|
| strip0 亮红 | 65 | (1.2, 1.6, 1.1) |
| strip0 亮绿 | 65 | (1.3, 1.7, 1.1) |
| strip0 亮蓝 | 65 | (1.3, 1.7, 1.1) |
| **全关 pmask=0** | **67** | (1.3, 1.7, 1.1) |

所以它是**环境光 / 桌面反光**，不是 LED 输出。这解释了
`stability-400s-2026-11-02.md` 里 strip 2/3 基线噪声超标（10.3° / 13.1°）
被排除的原因 —— 采样线穿过了这个固定光源，不是固件抖动。

**这条不影响本报告结论**（strip 0 的采样窗口在 y∈[535,620]，远离该亮线），
但它说明：要判定 strip 2/3，得先调机位避开那个反光。

## 8. 复现

```bash
# 需要 bleak + opencv；设备空闲、小程序退到后台
python <脚本>   # 本轮脚本是一次性的，逻辑已固化进下面的命令
```

固化的可复现步骤（用现有工具）：

```bash

# 2) 录像（同一相机会话内连续拍，不要每张重开）

       --width 1920 --height 1080 --exposure -11

# 3) 若要做稳定性判定，务必给 --reference，且基线紧邻录制

       --reference .runs/v3/base-before-stress.mp4
```
