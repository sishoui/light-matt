# 灯带点亮与电气基线

对应 GitHub issue [#4](https://github.com/sishoui/light-matt/issues/4) 与 wayfinder 票
[03-led-strip-smoke-test](./wayfinding/tickets/03-led-strip-smoke-test.md)。

本文只回答一件事：**在真实硬件上，用 `espressif/led_strip` 的 RMT backend 能不能稳定点亮
30 灯 WS2812B，颜色顺序是不是 GRB，电气边界在哪。** 灯效、BLE、协议、持久化都不在这里。

> **代码位置**：本票的 bring-up 固件保留在独立工程 `firmware/bringup/`（无 BLE、无协议、无 NVS），
> 用 `scripts\build-led-bringup.cmd` 构建、`scripts\flash-led-bringup.cmd COM6` 烧录。
> 正式产品固件在 `firmware/`，两者的 Kconfig 符号名共用。本票的交付物是「接线基线 + 实测结论」，
> 不是产品代码。

## 1. 结论摘要

| 项 | 结论 | 来源 |
|---|---|---|
| 依赖 | `espressif/led_strip` **3.1.1**（要求 IDF ≥5.2，本仓库 v5.4） | 构建日志 |
| RMT backend 在 C3 上初始化 | 通过（`led_strip_new_rmt_device` 返回 OK） | 串口日志 |
| 30 灯全亮、颜色均匀、无尾部衰减 | **通过**（用户肉眼确认） | 真机观察 |
| 纯红/纯绿/纯蓝与命令一致（GRB 假设） | **通过**：通道顺序就是 GRB，**不需要改成 RGB** | 真机观察 |
| 5 分钟常亮无闪烁、无重启 | 固件侧 5 分钟无复位、无 RMT 报错；用户观察未见异常 | 串口日志 + 真机 |
| 全白 255 是否掉压/重启 | 用户观察点灯序列整体正常，未见掉压/重启；**长期大电流使用仍需在 #14 验收中留意** | 真机观察 |
| 3.3V 直驱 5V 灯带 | **规格不达标**（VIH=3.5V），本块板实测可用；画板仍必须加 74AHCT125 | datasheet + 真机 |

固件侧已证明：复位原因、阶段时序、`refresh` 无错误、5 分钟 soak 心跳正常（见 §9.1）。
人眼确认：**颜色通道顺序为 GRB、30 灯颜色正确**（见 §9.2）。

**3.3V 直驱在规格上不达标却实测可用**，这正是研究笔记预期的「多数时候能亮」。它不构成可以省掉
电平转换的理由——温度、线长、批次差异都可能让首灯错色，画板时 74AHCT125 仍必须进 BOM。

## 2. 接线

### 2.1 连接图

```
   ESP32-C3 开发板                        WS2812B 灯带（30 灯，5V）
  ┌────────────────┐                    ┌────────────────────────────┐
  │                │                    │                            │
  │   GPIO3  ──────┼──[ 330Ω ]──────────┤ DIN                        │
  │                │      ^             │                            │
  │   GND  ────────┼────────────────────┤ GND                        │
  │                │                    │                            │
  │  (开发板 5V)   │  ── 仅短测可借用 ──┤ VCC  5V                    │
  │                │                    │                            │
  └────────────────┘                    └────────────────────────────┘
                                                   │  ▲
                                          DIN 在首灯，箭头指向尾部
                                         （接反不会亮，且不受软件控制）

  首灯 VCC/GND 之间并 500-1000µF / ≥6.3V 电解电容（靠灯带一端）
```

- **DIN 在灯带的首灯**，灯带上的箭头方向是数据流向。接反时整条不亮，这不是固件问题。
- **必须共地**：开发板 GND 与灯带电源 GND 必须连在一起。不共地时数据参考电平漂移，
  典型症状是首灯错色、整条随机闪烁、颜色在动但内容不对。
- **5V 供电**：30 灯全白约 **1.8A**（60mA/灯 × 30），开发板 USB 口通常只有 500mA-1A。
  短时测试可以从开发板 5V 脚取电，**全白阶段大概率掉压**；要完整跑高亮必须用独立 5V 电源。
- **首灯电容 500-1000µF / ≥6.3V**：吸收灯带颜色切换时的浪涌，防止首灯电压瞬间跌落导致错色。
- **数据线串 300-500Ω**：放在**靠近灯珠 DIN 的一端**（不是靠近 MCU 的一端），抑制反射与过冲。
- 数据线尽量短（<20cm）；长线更容易受 3.3V 电平问题影响。

### 2.2 电平转换（画板必须做）

开发阶段**故意不加**电平转换，目的是摸清这块板在临界状态下的真实表现。
但如果后续画 PCB，**必须**放一颗电平转换器：

| 器件 | 能否用 | 原因 |
|---|---|---|
| **74AHCT125** | 可以（推荐） | 5V 供电，**TTL 输入**，VIH=2.0V；3.3V 输入能被正确识别 |
| 74HCT245 | 可以 | 同上，TTL 输入 |
| 74HC125 | **不能** | **CMOS 输入**，5V 供电时 VIH≈3.5V，和直连一样不满足 |
| 直连 3.3V | 开发用 | 见 §3，规格不达标 |

注意 `AHCT`/`HCT` 里的 **T** 是关键；`HC` 系列看着像但不能替代。

## 3. 电气：3.3V 驱动 5V 灯带为什么不达标

WS2812B datasheet 的输入阈值（不是「建议值」，是规格）：

- **VIH = 0.7 × VDD** → 5V 供电时 **3.5V**
- VIL = 0.3 × VDD → 1.5V
- DIN 绝对最大输入 −0.5 ~ VDD+0.5V（3.3V 不会过压）

ESP32-C3 的 GPIO 高电平约等于 VDD = **3.3V**，低于 3.5V。**这是规格不满足，不是余量不足。**
芯片内部对 DIN 有施密特整形，实际能不能判成高电平取决于温度、批次、线长与噪声，
所以表现是「多数时候能亮，偶发首灯错色或整条闪一下」。

**怎么观察**：肉眼看灯带没有意义（单帧看不出来）。可靠的观察方式是

1. 让灯带保持一个固定颜色（本固件的 soak 阶段就是），
2. 同时用手机录像或长时间盯着，
3. 出现**偶发的单灯错色 / 整条闪一下 / 尾部先变色**，就是命中这个边界。

如果只有上电第一帧错、之后稳定，更像供电浪涌（查电容），而不是电平问题。

## 4. ESP32-C3FH4 引脚约束

C3FH4 是 QFN32 封装 + **封装内 4MB flash**，22 个 GPIO 里有相当一部分不能当普通 IO 用：

| GPIO | 状态 | 说明 |
|---|---|---|
| **GPIO3** | **可用（默认数据脚）** | 不在禁用名单内；默认驱动能力 10mA。驱动 WS2812B 的高阻 DIN 足够 |
| GPIO0 / GPIO1 | 可用 | XTAL_32K 脚，但可作普通 IO |
| GPIO2 | 避免 | strapping（启动模式）；建议外部上拉躲 power-up glitch |
| GPIO4-7 | 避免 | JTAG（MTCK/MTDO/MTDI/MTMS） |
| GPIO8 | 避免 | strapping（启动模式） |
| GPIO9 | 避免 | strapping，内部弱上拉默认为 1；按下 BOOT 会改启动模式 |
| GPIO10 | 可用 | — |
| GPIO11 | 不要用 | VDD_SPI，除非 flash 由外部供电 |
| GPIO12-17 | **不可用** | SPI0/1 接**封装内 flash**，占用后无法启动 |
| GPIO18 / GPIO19 | **不可用（若用原生 USB）** | USB Serial/JTAG 的 D-/D+；占用后串口日志与烧录都断 |
| GPIO20 / GPIO21 | **不可用（若用 UART0）** | U0RXD / U0TXD；本仓库的烧录与 monitor 走 UART0 |

本固件默认 **GPIO3**，可用 `idf.py menuconfig` → `Lumen 灯带` → `灯带数据脚 GPIO` 改。

> 开发板上的丝印编号和芯片 GPIO 编号不一定一致，接线前对照板子的引脚图确认。

## 5. 固件行为

### 5.1 测试序列

上电（或按 RST）后自动循环。每阶段在串口打印阶段名、期望现象、命令 RGB、亮度，
以及**经过线性缩放后真正下发到灯珠的 RGB**。

| # | 阶段名 | 命令 RGB | 亮度 | 时长 | 人眼应看到 |
|---|---|---|---|---|---|
| 1 | `red` | 255,0,0 | 255 | 2s | 整条纯红，均匀，尾部不衰减 |
| 2 | `green` | 0,255,0 | 255 | 2s | 整条纯绿 |
| 3 | `blue` | 0,0,255 | 255 | 2s | 整条纯蓝 |
| 4 | `warm_low` | 255,180,120 | 1 | 2s | 极暗，几乎看不清（1/255） |
| 5 | `warm_mid` | 255,180,120 | 128 | 2s | 暖白，中等亮度 |
| 6 | `white_high` | 255,255,255 | 255 | 3s | 全白最亮，约 1.8A |
| 7 | `off` | 0,0,0 | 0 | 5s | 全灭，无单灯微亮 |
| — | `soak` | 255,0,0 | 128 | **5min** | 恒定暗红，不闪不灭 |

序列总长 18s，然后进入 5 分钟 soak（每 30s 一行心跳），soak 结束后回到序列，无限循环。

**亮度是线性缩放，不是 gamma。** WS2812B 没有全局亮度寄存器，只能在写入前把系数乘到 RGB 上。
本票刻意不做 gamma：要观察的是电气与通道顺序，线性缩放至少保证 1/255 就是真的 1/255。
副作用：亮度 1 时 `(255,180,120)` 量化成 `(1,1,0)`，看起来会偏黄绿而不是暖白，**这是整数取整，
不是通道顺序问题**。

### 5.2 Kconfig

`firmware/main/Kconfig.projbuild`，menuconfig 路径 `Lumen 灯带`：

| 符号 | 默认 | 说明 |
|---|---|---|
| `CONFIG_LUMEN_LED_GPIO` | 3 | 数据脚 |
| `CONFIG_LUMEN_LED_COUNT` | 30 | 灯珠数 |
| `CONFIG_LUMEN_RMT_MEM_BLOCK_SYMBOLS` | 48 | 与 C3 每通道 48 word 对齐 |
| `CONFIG_LUMEN_LED_COLOR_ORDER_GRB` / `_RGB` | GRB | 通道顺序 |

`resolution_hz` 固定 10MHz，`with_dma=false`（C3 的 RMT **没有 DMA**，这是硬约束）。

> 这些符号名是 #4 与 #6 的共用约定，后续加配置时**不要改名**，否则合并时会打架。

## 7. 用户验收步骤

按顺序做，每步都有明确的判据。

### 步骤 0：上电前检查

- [ ] 灯带 DIN 接 GPIO3，**不是** DOUT
- [ ] 灯带 5V 与开发板 GND **共地**
- [ ] 首灯处有 500-1000µF / ≥6.3V 电容（有极性，别接反）
- [ ] 数据线串了 300-500Ω（靠灯珠一端）
- [ ] 灯带供电电压实测接近 5V

### 步骤 1：烧录并确认固件在跑

```bat
scripts\build-led-bringup.cmd
scripts\flash-led-bringup.cmd COM6
```

串口应出现：

```
lumen #4 LED bring-up（独立 bring-up 工程）
reset_reason=2 (POWERON) uptime=0.052s   ← 或 11 (USB)，烧录后首次启动常见
strip: gpio=3 leds=30 color_order=GRB mem_block_symbols=48 ...
```

若 `reset_reason` 是 `BROWNOUT` 或 `PWR_GLITCH`，先查供电再看灯。

### 步骤 2：逐阶段对照（对应 #4 验收项 1、2）

盯着灯带，同时看串口：

| 串口出现 | 应看到 | 不合格的表现 |
|---|---|---|
| `[stage 1/7] red` | 纯红 | 看到绿 → 通道顺序是 RGB；看到蓝 → 其他顺序 |
| `[stage 2/7] green` | 纯绿 | 看到红 → R/G 互换 |
| `[stage 3/7] blue` | 纯蓝 | 蓝不对 → B 通道也错，记录实际看到的顺序 |
| `[stage 4/7] warm_low` | 极暗，勉强可见 | 完全不亮 → 低亮度边界（可接受，记录） |
| `[stage 5/7] warm_mid` | 暖白中亮 | 与 warm_low 无差别 → 亮度缩放有问题 |
| `[stage 6/7] white_high` | 全白，非常亮 | 变暗/闪/板子重启 → 供电不足 |
| `[stage 7/7] off` | 全灭 | 单灯微亮 → 查共地与串阻 |

**判断 GRB 顺序**：只看 `red` 与 `green` 两段就够。
命令 `red` 时如果亮**绿**、命令 `green` 时亮**红**，就是 R/G 互换，把 Kconfig 改成 RGB：

```bat
idf.py menuconfig   → Lumen 灯带 → 颜色通道顺序 → RGB
```

若 `red` 亮**蓝**，说明不是简单的 R/G 互换，记录三段实际颜色后回来改代码。

**判断尾部衰减**：看 `red` 阶段最后几颗灯是否和第一颗一样亮。
明显偏暗说明供电注入点只在首端、线损过大 → 两端供电或加粗线。

### 步骤 3：全白观察（对应 #4 验收项 4）

`white_high` 只有 3 秒，专注于：

- 灯带是不是**整体变暗**（掉压）而不是变白
- 有没有**闪一下**或颜色抖动
- 开发板有没有重启（串口日志会从头出现）

如果板子重启，重启后的第一行 `reset_reason` 会告诉你是不是掉压。
本固件目前**不做**编译期亮度上限；这条结论决定 #6 是否要加 `max_brightness`。

### 步骤 4：5 分钟 soak（对应 #4 验收项 3）

序列结束后自动进入 soak：暗红、5 分钟、每 30s 一行心跳：

```
[soak] 心跳 1/10：已常亮 30s，剩余 269s，heap=316216 min_heap=316216 refresh_errors=0
```

- 灯带应保持**恒定暗红**，不闪、不灭、不偏色
- 串口心跳应连续编号 1/10 → 10/10，**中间不能断**
- 若日志从 `lumen #4 LED bring-up` 重新开始，就是重启了，看 `reset_reason`
- 若出现心跳但灯带在闪 → 这是 RMT/中断层面的问题，记下来交给 #7

`refresh_errors` 在 soak 结束时会打印累计值，应为 0。

### 步骤 5：回传

把**串口完整日志**（从启动横幅到最后一行）+ 上面每一步的**肉眼观察**一起回传。
颜色、闪烁、掉压这三项无法从日志推断，必须由观察者描述。

## 8. 现象 → 结论

| 现象 | 结论 | 下一步 |
|---|---|---|
| `red` 阶段看到**绿色** | 通道顺序不是 GRB，是 **RGB** | Kconfig 改 RGB，重烧验证 |
| `red` 阶段看到**蓝色** | 通道顺序既不是 GRB 也不是 RGB | 记录三段实际颜色，改代码里的 format |
| 三段颜色都对，但某一段偏色 | 该通道 LED 正向压降差异或供电不均 | 降低亮度复测；仍偏则记录灯带批次问题 |
| 只有第 1 颗灯亮 / 前几颗亮 | 数据没传下去：DIN/DOUT 接反、灯带方向反、串阻过大 | 检查方向与串阻 |
| 整条不亮，但日志 `refresh` 正常 | 数据没进灯带：DIN 未接、灯带没供电、方向反 | 万用表量 DIN 与 VCC |
| 偶发单灯错色 / 整条闪一下 | **3.3V 驱动 5V 的 VIH 未满足**（最常见） | 画板加 74AHCT125；开发阶段可接受 |
| 上电第一帧错色，之后稳定 | 电源浪涌 | 检查首灯电容与线径 |
| 全白时整体变暗 / 板子重启 | **5V 供电不足**（USB 限流） | 独立 5V 电源；或固件加 `max_brightness` |
| 串口从头开始 + `reset_reason=BROWNOUT`/`PWR_GLITCH` | 硬件掉压复位 | 同上；这是电气结论，不是软件 bug |
| 尾部灯珠偏暗/偏色 | 线损，供电只从首端注入 | 两端供电 / 加粗线 / 降亮度 |
| `warm_low` 完全不亮 | 亮度 1 的量化边界（`(1,1,0)`），WS2812B 低位非线性 | 可接受；正式固件加 gamma 或提高最低亮度 |
| `warm_low` 偏黄绿而非暖白 | 亮度 1 时整数取整把 B 通道归零 | 正常，不是通道顺序问题 |
| `off` 后有单灯微亮 | 共地不良 / 数据线残留 / 串阻缺失 | 查共地与串阻 |
| 心跳连续但灯带在闪 | 不是供电问题，是 RMT × 中断/射频 | 记录并交给 #7 |
| `led_strip_new_rmt_device` 失败 | GPIO 被占用或 RMT 通道不足 | 换 GPIO，确认没有别的驱动占 RMT |
