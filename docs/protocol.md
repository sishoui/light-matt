# lumen 协议规格 v1

**状态**：定稿（2026-10-29）
**适用范围**：微信小程序 ↔ ESP32-C3 固件之间的 BLE 协议。
**唯一真相**：本文件定义字节级契约，`docs/protocol-testvectors.json` 是它的可执行副本。改协议 = 本文件 + 测试向量 + 两端实现进同一个 commit。
**相关**：[架构基线](./wayfinding/architecture-brief.md)、[实现规格](./spec.md)、[研究笔记](./wayfinding/research/ble-and-firmware-facts.md)。

---

## 1. 角色与链路

- **小程序**是 central：写 RX、订阅 TX、读 State。
- **设备**是 peripheral：单连接，不配对，不绑定。
- 所有多字节字段 **小端**。
- 帧总长 **≤ 20 字节**（BLE 默认 ATT MTU 23 − 3）。本协议不定义分包/重组；所有载荷都远低于预算。

## 2. GATT

| 项 | UUID | 属性 | 方向 |
|---|---|---|---|
| Service | `6c756d65-6e00-4b1e-9a3c-000000000001` | — | — |
| RX | `6c756d65-6e00-4b1e-9a3c-000000000002` | write-no-response | 小程序 → 设备 |
| TX | `6c756d65-6e00-4b1e-9a3c-000000000003` | notify | 设备 → 小程序 |
| State | `6c756d65-6e00-4b1e-9a3c-000000000004` | read | 小程序读设备 |

- **广播包**：flags + 128-bit Service UUID。
- **扫描响应包**：完整本地名 `Lumen-XXXX`，XXXX = 蓝牙 MAC 最后 2 字节的大写十六进制。
- **只允许 1 个连接**；断开后重新开始广播。
- **连接参数请求**：15-30ms interval，latency 0，优先保证拖动跟手，不追求省电。
- State read 固定 **8 字节**，布局见 §7。

## 3. 帧格式

| 偏移 | 字段 | 宽度 | 说明 |
|---|---|---|---|
| 0 | magic | 1 | 固定 `0xA5` |
| 1 | version | 1 | 固定 `0x01` |
| 2 | command | 1 | 命令字，见 §5 / §6 |
| 3 | seq | 1 | 请求序号，见 §9 |
| 4 | length | 1 | **载荷长度**，0-14 |
| 5..5+length-1 | payload | length | 载荷 |
| 5+length | checksum | 1 | 校验和 |

- **整帧长度 = 6 + length**，必须 ≤ 20。
- **checksum** = 对 `magic` 到 `payload` 最后一个字节求和，取低 8 位，再**按位取反**（one's complement，不是取负）。checksum 自己不参与计算。
- 设备 → 小程序的帧（ACK / Event / StateReport）使用完全相同的信封、version 与校验算法。

### 校验和例子

帧 `A5 01 01 01 01 01`：

```
sum = A5 + 01 + 01 + 01 + 01 + 01 = 0xAA
checksum = ~0xAA & 0xFF = 0x55
完整帧 = A5 01 01 01 01 01 55
```

可执行伪代码：

```
sum = 0
for i in 0 .. (5 + length - 1):
    sum = (sum + frame[i]) & 0xFF
checksum = (~sum) & 0xFF
```

## 4. 版本

- `version = 0x01`。
- 设备遇到未知 version：回 ACK `0x07`，不执行。
- 小程序遇到未知 version：视为协议不匹配，提示用户升级，不继续解析。
- 不兼容的协议变更必须提升 version；MVP 只有一个版本值。

## 5. 结果码

ACK 载荷的第二个字节：

| 值 | 名称 | 含义 |
|---|---|---|
| `0x00` | OK | 已接受并写入 RAM |
| `0x01` | InvalidParam | 参数越界或取值非法 |
| `0x02` | UnknownCommand | 未知/保留命令字 |
| `0x03` | BadChecksum | 校验失败 |
| `0x04` | BadLength | 帧长度或命令载荷长度错误 |
| `0x05` | Busy | 暂时无法执行，可稍后重试 |
| `0x06` | StorageFailed | 同步存储失败（v1 保留；异步失败用 Event） |
| `0x07` | UnsupportedVersion | 不支持的协议版本 |
| `0x08` | BadMagic | magic 不是 `0xA5` |
| `0x09` | InternalError | 资源/句柄重建失败 |

`0x0A-0x0F` 保留。

## 6. 命令（小程序 → 设备）

| 命令字 | 名称 | 载荷 | 合法值 | 错误 |
|---|---|---|---|---|
| `0x01` | SetPower | 1 字节：power | 0 / 1 | 其他 → `0x01` |
| `0x02` | SetBrightness | 1 字节：brightness | 0-255 | 无 |
| `0x03` | SetColor | 3 字节：R, G, B | 各 0-255 | 无 |
| `0x04` | SetAll | 5 字节：power, brightness, R, G, B | power 0/1；其余 0-255 | power 非法 → `0x01`，整帧不生效 |
| `0x05` | QueryState | 0 字节 | — | 参见 §6.1 |
| `0x06` | SetLedCount | 2 字节小端：count | 1-64 | 越界 → `0x01` |
| `0x07` | SelfTest | 0 字节 | — | 参见 §11.2 |

- `0x08-0x7F` 保留给后续命令；设备收到时回 `0x02`。
- 小程序写入 `0x80-0xFF`（ACK / Event / StateReport 等设备→小程序命令）→ `0x02`。
- 载荷长度与命令要求不符 → `0x04`，整帧不执行。
- 所有载荷 ≤ 5 字节；14 字节预算下不需要分包。

### 6.1 查询状态

`0x05` 收到后：

1. 回 ACK `0x80`，载荷 `[0x05, 0x00]`，seq 回显请求的 seq。
2. 紧接着回 StateReport `0x82`，载荷为 8 字节状态，seq 同样回显。

State read 是主同步路径；查询状态是次要/调试路径，两者返回完全相同的 8 字节布局。

## 7. State 布局与语义

State 特征值 read 与 StateReport 载荷都是 8 字节：

| 偏移 | 字段 | 宽度 | 说明 |
|---|---|---|---|
| 0 | power | 1 | 0 关 / 1 开 |
| 1 | brightness | 1 | 0-255，已按 `max_brightness` 钳位后的生效值 |
| 2 | R | 1 | 0-255 |
| 3 | G | 1 | 0-255 |
| 4 | B | 1 | 0-255 |
| 5 | led_count_lo | 1 | 灯珠数量低字节 |
| 6 | led_count_hi | 1 | 灯珠数量高字节 |
| 7 | max_brightness | 1 | 固件当前亮度上限，初值 255 |

- State read 必须正好 8 字节；长度不符视为协议不匹配。
- `max_leds = 64` 是协议常量，不放进 State；两端硬编码。
- **开关与亮度独立存储**：亮度 0 且开关为 1 是合法状态，视觉上等于关灯；把亮度拖到 0 不会清掉开关位，拖回来就恢复。
- 关灯保留亮度。
- SetAll 即使 power = 0，载荷里的亮度/RGB 也会被保存。
- 设备是状态权威：小程序连上后读 State，不用本地缓存覆盖设备。

## 8. 设备 → 小程序帧

| 命令字 | 名称 | 载荷 | seq |
|---|---|---|---|
| `0x80` | ACK | 2 字节：`[原命令字, 结果码]` | 回显请求 |
| `0x81` | Event | 2 字节：`[event_code, detail]` | 固定 `0x00` |
| `0x82` | StateReport | 8 字节状态，布局同 §7 | 回显查询请求 |

- Event code：`0x01` = 存储失败（detail = 触发写入的原命令字）；`0x02-0xFF` 保留。
- `0x83-0xFF` 保留。
- ACK / Event / StateReport 本身不再回 ACK。
- 设备**不主动推送状态**；StateReport 只在查询状态时发送。

## 9. seq 语义

- 每条连接从 `0x01` 开始，每发一帧 +1，`0xFF` 后回 `0x00`。
- 新连接重置为 `0x01`。
- 设备原样回显请求的 seq；**不去重**。写操作串行化 + 命令都是绝对值，重传不会造成状态翻转。
- Event 的 seq 固定 `0x00`；StateReport 回显查询请求的 seq。

## 10. ACK 时序与错误处理

### 10.1 正常时序

```
校验通过 → 写入共享状态（RAM）→ 发渲染信号 → 回 ACK
```

- ACK `0x00` 的含义是「**已接受并写入 RAM**」，不保证已经渲染完或已经写进 NVS。
- 校验失败 / 参数越界：回对应错误码的 ACK，**不写入状态**。
- **例外：SetLedCount**。ACK 要等句柄重建成功/失败之后才发，结果码取决于重建结果（§11.3）。

### 10.2 校验顺序

固定顺序：

```
magic (0x08) → version (0x07) → length (0x04) → checksum (0x03)
→ command (0x02) → payload 长度 (0x04) → payload 取值 (0x01)
```

- 长度错误优先于校验和：长度不对就无法定位校验和字节。
- **整帧不足 6 字节**：无法可靠读出 seq，直接丢弃，不回 ACK。
- **实际长度与 length 不符**（多、少、拖尾）→ `0x04`。
- **payload > 14 或整帧 > 20** → `0x04`。
- 坏 checksum 的帧尽力回显 header 里的 seq/命令字；小程序匹配不上就按超时处理。
- 未知命令 / 保留命令 / 小程序写入设备→小程序命令字 → `0x02`。
- 已知命令的载荷长度不符 → `0x04`；载荷取值非法 → `0x01`。
- 任何错误都不改变状态。

### 10.3 异步错误

- NVS 写失败发生在 ACK 之后，用 Event `0x81` 上报：载荷 `[0x01, 原命令字]`，seq `0x00`。
- 小程序收到后显示非阻塞警告，不回 ACK。
- 自检不写 NVS，因此不会产生存储失败 Event。

## 11. 行为语义

### 11.1 SetAll 原子性

`0x04` 的 5 个字段要么全部生效，要么全部不生效。power 不是 0/1 时回 `0x01`，亮度与 RGB 也不写入。

### 11.2 自检

收到 `0x07` 后：

1. 立即回 ACK `0x00`。
2. 渲染任务按 **红 → 绿 → 蓝 → 白** 依次输出，每色 500ms，共 2s；每色亮度取当前 `max_brightness`。
3. 自检是**临时覆盖**：不写 NVS，不改共享状态；结束后恢复自检前的开关/亮度/颜色。
4. 即使自检开始时是关灯态，也会点亮；结束后回到关灯。
5. 任何改变状态的命令（开关/亮度/颜色/一次设全部/灯珠数量）立即取消自检并应用新命令。
6. 查询状态不取消自检；State read / StateReport 返回存储状态，不是自检颜色。
7. 重复收到自检命令则重新开始序列；不发送完成事件。

### 11.3 灯珠数量重建

收到合法的 `0x06` 后：

1. 渲染任务重建 `led_strip` 句柄；重建完成后才回 ACK。
2. **成功**：ACK `0x00`，新数量立即生效，当前开关/亮度/颜色保持不变，随后按 §12 持久化。
3. **失败**：保留旧句柄和旧数量，状态不变，ACK `0x09`。
4. 重建进行中收到第二个 `0x06` → ACK `0x05`，不排队。
5. 重建期间的其它命令正常写入共享状态；重建完成后按最新状态渲染。
6. NVS 写失败不影响已经生效的数量，按 §10.3 上报。
7. **数量减少时，超出新数量的灯珠必须熄灭。** WS2812B 每颗灯会锁存最后一次
   收到的像素，新句柄只驱动前 N 颗，其余灯收不到数据就会停留在旧颜色上。
   固件在删除旧句柄前，必须先用旧数量把整条灯带写成 0 再 refresh 一次。
   这是协议要求的行为（用户视角「新数量立即生效」包含「多余的灯灭掉」），
   不是实现细节。

### 11.4 亮度钳位

- 协议亮度范围是 0-255；固件可以按构建期常量 `max_brightness` 钳位。
- State 的 `max_brightness` 暴露当前上限，小程序滑块最大值直接用它。
- 初值 255（暂不限制）；#4 点灯验证出供电结论后再改固件常量与协议默认值。小程序不硬编码上限。

## 12. 持久化与默认值

- 持久化字段：开关、亮度、RGB、灯珠数量。
- 任意变更后 **500ms debounce** 写 NVS。
- 上电恢复；恢复失败回默认值。
- 自检不写 NVS。
- 默认值（无 NVS 历史时）：

| 字段 | 默认值 |
|---|---|
| power | 0（关） |
| brightness | 128 |
| R, G, B | 255, 180, 120（暖白） |
| led_count | 30 |
| max_brightness | 255（构建期常量） |

## 13. 测试向量

文件：`docs/protocol-testvectors.json`。两端 codec 必须跑同一份文件并全绿。

顶层字段：

- `protocol_version`：1
- `checksum`：算法说明
- `frame_layout`：帧布局说明
- `state_read_example_hex`：8 字节 State 示例
- `state_read_fields`：字段顺序
- `cases`：用例数组

每个用例：

| 字段 | 说明 |
|---|---|
| `name` | 用例名 |
| `direction` | `app_to_device` / `device_to_app` |
| `command` | 命令字（无效帧可缺省） |
| `command_name` | 命令名（可选） |
| `seq` | 序号（无效帧可缺省） |
| `payload_hex` | 载荷（有效帧） |
| `frame_hex` | 完整帧 hex |
| `frame_valid` | 信封是否有效 |
| `result_code` | 设备应回的结果码；`null` 表示静默丢弃；设备→小程序帧可缺省 |
| `note` | 可选说明 |

覆盖范围：开关、亮度、颜色、一次设全部、查询、灯珠数量、自检、ACK 各结果码、StateReport、Event、坏校验、坏 magic、短帧、长度不符、超长、未知命令、保留命令、非法取值、错误载荷长度。

## 14. 变更规则

- 改协议 = 本文件 + 测试向量 + 两端实现进同一个 commit。
- 不兼容变更提升 `version`；读端遇到未知 version 回 `0x07`，不尝试兼容解析。
- UUID、命令字、结果码、State 布局都是协议的一部分，不得单端修改。
