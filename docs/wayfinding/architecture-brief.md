## 项目定位

用微信小程序通过 BLE 直连控制 ESP32-C3FH4 驱动的 WS2812B 灯带。
本 effort 的终点是**已打通的原型**，不是量产产品。

## 通信

| 项 | 决定 |
|---|---|
| 通道 | BLE 直连（GATT），不走 WiFi / MQTT |
| 配对 | 不做 bonding / 不要求配对，开放式连接 |
| 并发连接 | 只允许 1 个中心设备连接 |
| 发现方式 | 固定 Service UUID 过滤扫描；广播名 `Lumen-XXXX`（XXXX 为短 ID 后缀） |
| 回连 | 缓存 `deviceId`，进前台静默回连；失败后有限次退避重试（1s/2s/4s），仍失败则回「未连接」提示手动重连 |
| 初始化序列 | 连接成功 → 协商 MTU（**仅 Android 5.1+**；iOS 无此 API，直接跳过）→ 订阅 notify → **留间隔或先 read 一次** → 读 State 同步 UI |

## GATT 结构

一个 Service，三个 Characteristic：

- **RX** — 小程序写入指令，`write-no-response` 属性
- **TX** — 设备 notify 上行（ACK / 错误 / 主动上报）
- **State** — `read`，一次读取即得完整当前状态（断线重连后靠它同步，不等设备主动推）

## 帧格式

二进制紧凑帧，控制在默认 MTU 单帧内，不分包：

```
[0] magic    0xA5
[1] version  协议版本
[2] command  命令字
[3] seq      序号（ACK 回显以关联）
[4] length   载荷长度
[5..N] payload
[N+1] checksum  求和取反
```

### 20 字节是硬约束（研究结论，非假设）

- BLE 默认 ATT MTU 为 23，减去 3 字节 ATT 头，**单次实际可写 20 字节**。
- `wx.setBLEMTU` **仅 Android 5.1+ 有效，iOS 完全没有这个 API**，由系统自行协商。
- **iOS 上超长写入会静默失败**——既无 success 也无 fail 回调。所以客户端必须自己按 `maximumWriteValueLength` 分包，**不能依赖错误回调触发重传**。
- 因此：**协议设计按 20 字节上限做，帧总长必须 ≤ 20 字节**；MTU 协商成功只是可选优化，不是前提。
- 当前帧骨架的开销为 `magic(1) + version(1) + command(1) + seq(1) + length(1) + checksum(1) = 6` 字节，留给 payload 的是 **14 字节**。这个预算必须在【协议规格定稿】里核算过。

### 传输时序

- 小程序端滑动类连续量最多 20Hz 发包，**新值覆盖未发出的旧值**（不排队）
- `writeType` 显式指定：RX 特征用 `writeNoResponse`；写入调用必须**串行化**，禁止并行多次调用（官方明确会写失败）
- **Android 上 notify 成功后立刻 write 会报 10008** —— 初始化序列里 notify 与首次 write 之间必须有间隔（或先做一次 read）
- 设备对每帧回短 ACK（回显 seq + 结果码）
- 连续量（颜色/亮度）不重传，超时只作为「可能断线」信号触发重连检查
- 非幂等操作（开关）可重传一次
- **错误码分流**：`10006` = 连接已断 → 走重连，**不要重试写**；`10008` = 系统兜底异常 → 检查是否踩了 notify-后-立即-写
- `10001`（适配器不可用 / 蓝牙未开）**不是致命错误**，蓝牙模块已初始化，应等 `onBluetoothAdapterStateChange` 再继续

## 状态模型

- 开关与亮度**解耦**：关灯保留亮度值，再开恢复原亮度；亮度拉到 0 等价于关灯
- 颜色模型：小程序用 HSV 取色，换算为用户空间 RGB（0-255，不做 gamma）下发；独立全局亮度 0-255
- 固件做 gamma 校正后再乘亮度，保证低亮度不偏色
- 灯珠数量：编译期默认值 + 小程序可改，改后写 NVS
- 断电记忆：状态变更后 debounce 写 NVS，上电恢复

### 关键风险：C3 的 RMT 没有 DMA，且是单核

研究确认（官方 `soc_caps.h` + led_strip README）：

- ESP32-C3 **没有 `SOC_RMT_SUPPORT_DMA`**（S3 才有）。WS2812 波形由 ISR 逐块编码输出。
- led_strip README 原文警告：若 RMT 中断被延迟（例如同核上发生 Wi-Fi 中断），**RMT 事务会损坏，灯珠显示错误颜色**。
- 官方缓解措施之一是「把 RMT 驱动装到另一个核」——**C3 是单核，这条不可用**。
- C3 只有一个 2.4GHz 射频，Wi-Fi/BLE 时分复用；BLE 连接事件会周期性抢占中断。

**因此这不是「可能有问题」，而是「默认可疑」**。可用的缓解手段只剩：

1. 加大 `mem_block_symbols`（48 的整数倍，默认就是 48，需要实测调优）
2. 编码相关函数放 IRAM
3. 降低刷新频率（只在状态变化时刷，不做固定帧率空转）——这正是 latest-wins 模型的额外好处
4. 用 `refresh_async` + 双缓冲自建，避免 `refresh()` 阻塞渲染任务

这条风险必须有独立验证票，不能埋在【固件协议实现】里。

### 电气：3.3V 驱动 5V WS2812B 在规格上不达标

- WS2812B datasheet：**VIH = 0.7 × VDD**。5V 供电 → VIH = **3.5V**。C3 输出高电平约 3.3V。
- **这是规格不满足，不是「可能有问题」**。表现为「多数时候能亮，偶发首灯错色或整条闪烁」。
- Adafruit 官方教程明确要求 3.3V MCU 必须加 **74AHCT125 / 74HCT245**（TTL 输入，5V 供电，VIH=2.0V，可识别 3.3V）。**不能用 74HC125**（CMOS 输入，5V 下 VIH≈3.5V，同样不达标）。
- 同页建议：首灯并 **500-1000µF / ≥6.3V** 电容；数据线串 **300-500Ω** 电阻（靠近灯珠一端）。
- 现状取舍：开发阶段用开发板 USB 5V 供电、短灯带（30 灯）、暂不加电平转换，**接受偶发异常作为已知限制**。但你后续画板时这颗缓冲器必须进 BOM。

### 电流预算

- 单灯全白最大 60mA（3 通道 × 20mA，Adafruit 通用值；WS2812B datasheet 本身未标注电流项）。
- 30 灯全白 ≈ **1.8A**。开发板 USB 5V 通常限流 500mA-1A —— **全白高亮度会拉爆**。
- 因此 MVP 阶段必须限制亮度上限，或在验证票里明确「全白只短暂测试」。

## 真机验收清单（7 条）

1. 小程序扫到设备并连上，MTU 协商成功或优雅降级
2. 开关按钮能亮灭灯带，回包 ACK 序号正确
3. 拖动亮度滑块灯带实时跟随，无可感延迟
4. 色环选色后灯带颜色正确、无偏色
5. 断线后自动回连并恢复 UI 状态
6. 断电重启后颜色/亮度/开关恢复
7. 小程序端协议日志能看到每一帧
