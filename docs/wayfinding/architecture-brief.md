## 项目定位

用微信小程序通过 BLE 直连控制 ESP32-C3FH4 驱动的 WS2812B 灯带。
本 effort 的终点是**已打通的原型**，不是量产产品。

## 通信

| 项 | 决定 |
|---|---|
| 通道 | BLE 直连（GATT），不走 WiFi / MQTT |
| 配对 | 不做 bonding / 不要求配对，开放式连接 |
| 并发连接 | 只允许 1 个中心设备连接 |
| 发现方式 | 固定 Service UUID 过滤扫描；广播名 `Lumen-XXXX`（XXXX 为短 ID 后缀） |
| 回连 | 缓存 `deviceId`，进前台静默回连；失败后有限次退避重试（1s/2s/4s），仍失败则回「未连接」提示手动重连 |
| 初始化序列 | 连接成功 → 协商 MTU（失败则按默认 MTU 降级）→ 订阅 notify → 读 State 特征值同步 UI |

## GATT 结构

一个 Service，三个 Characteristic：

- **RX** — 小程序写入指令，`write-no-response` 属性
- **TX** — 设备 notify 上行（ACK / 错误 / 主动上报）
- **State** — `read`，一次读取即得完整当前状态（断线重连后靠它同步，不等设备主动推）

## 帧格式

二进制紧凑帧，控制在默认 MTU 单帧内，不分包：

```
[0] magic    0xA5
[1] version  协议版本
[2] command  命令字
[3] seq      序号（ACK 回显以关联）
[4] length   载荷长度
[5..N] payload
[N+1] checksum  求和取反
```

- 小程序端滑动类连续量最多 20Hz 发包，**新值覆盖未发出的旧值**（不排队）
- 设备对每帧回短 ACK（回显 seq + 结果码）
- 连续量（颜色/亮度）不重传，超时只作为「可能断线」信号触发重连检查
- 非幂等操作（开关）可重传一次

## 状态模型

- 开关与亮度**解耦**：关灯保留亮度值，再开恢复原亮度；亮度拉到 0 等价于关灯
- 颜色模型：小程序用 HSV 取色，换算为用户空间 RGB（0-255，不做 gamma）下发；独立全局亮度 0-255
- 固件做 gamma 校正后再乘亮度，保证低亮度不偏色
- 灯珠数量：编译期默认值 + 小程序可改，改后写 NVS
- 断电记忆：状态变更后 debounce 写 NVS，上电恢复

## 固件

| 项 | 决定 |
|---|---|
| 框架 | 纯 ESP-IDF v5.4（本机源码位于 `C:\Users\13092\esp\v5.4\esp-idf`） |
| BLE 栈 | NimBLE |
| 驱动 | `espressif/led_strip` 组件，RMT backend |
| 灯带 | WS2812B，GRB 顺序，约 30 灯珠，开发板 USB 5V 供电，暂不做电平转换 |
| 数据脚 | 默认 GPIO3，Kconfig 可配（备选 GPIO4/5/10）<br>C3FH4 约束：GPIO11-17 被内置 flash 占用、18/19 为 USB-JTAG、2/8/9 为 strapping |
| 分层 | `ble_link`（GATT + 帧收发）/ `led_engine`（状态 + gamma + 渲染）/ `state_store`（NVS），三层独立可测 |
| 渲染触发 | 共享状态 + latest-wins 邮箱 + 独立渲染任务；BLE 回调只写状态并发信号量，永不阻塞，渲染永远取最新一帧 |
| 日志 | ESP_LOG 串口输出，配合 `idf.py monitor` |

## 小程序

| 项 | 决定 |
|---|---|
| 技术栈 | 原生小程序 + TypeScript 模板 |
| AppID | 测试号（BLE 不依赖服务器域名） |
| 页面结构 | 单页面 + 扫描/连接弹层 |
| 控件 | 顶部连接状态条 → 开关 → 亮度滑块 → 色环取色器 → 一排预设色块（6-8 个） |
| 调试 | 开发版把每帧 hex 打到 console；页面上有隐藏「协议日志」面板（连点版本号 5 次开启），含时间戳 / 方向 / hex / 解析后的命令名与参数，带暂停、清空、复制 |

## 仓库结构

```
lumen/
  firmware/     ESP-IDF 工程
  miniprogram/  小程序工程
  docs/         协议规格、接线说明、构建烧录步骤、wayfinding 地图
```

两端独立构建，只通过协议文档耦合；改协议时两边改动进同一个 commit。

## 真机验收清单（7 条）

1. 小程序扫到设备并连上，MTU 协商成功或优雅降级
2. 开关按钮能亮灭灯带，回包 ACK 序号正确
3. 拖动亮度滑块灯带实时跟随，无可感延迟
4. 色环选色后灯带颜色正确、无偏色
5. 断线后自动回连并恢复 UI 状态
6. 断电重启后颜色/亮度/开关恢复
7. 小程序端协议日志能看到每一帧
