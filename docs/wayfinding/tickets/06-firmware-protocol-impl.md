# 06：固件协议实现与状态机

**类型**：`wayfinder:task`（AFK，末尾需真机确认）

## Question

把 `protocol.md` 的命令表在固件侧全部实现，状态机覆盖「开关 / 亮度 / 颜色 / 灯珠数量 / 自检」的组合，并让 NVS 持久化与 ACK 时序都符合规格。

这一票是把骨架填成器官。风险点不在写代码，在**边界语义**：越界是钳位还是拒绝、ack 在状态生效前还是后发、NVS 写入失败要不要回错误、灯珠数量变更时 ledger 句柄重建期间的刷新怎么处理。

### 要实现的

1. 帧解码器：长度校验、magic 校验、checksum 校验，任一失败按协议回对应结果码
2. 命令分发：开关 / 亮度 / 颜色 / 一次设全部 / 查询状态 / 设灯珠数量 / 自检
3. 状态机：开关与亮度解耦，颜色独立，任一变更触发渲染 + debounce 持久化
4. ACK：每帧回显 seq + 结果码，时序符合协议规定
5. State 特征值 read 返回当前完整状态
6. 灯珠数量运行时可改：重建 led_strip 句柄，失败时回滚并保持旧配置
7. gamma 校正表 + 亮度乘算，低亮度不偏色
8. 上电从 NVS 恢复，恢复失败回默认值

### 边界语义（写代码前必须在协议里查清）

- 亮度 0 是否等价关灯、与开关字段冲突时谁优先
- 灯珠数量越界（0 或超上限）的处理
- 自检帧期间收到正常指令怎么办（打断还是排队）
- NVS 写失败时 ACK 回什么
