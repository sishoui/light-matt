# 07：小程序 BLE 传输层与协议 codec

**类型**：`wayfinder:task`（AFK — 我能独立完成）

## Question

小程序侧的 BLE 传输层怎么封装，才能让 UI 层完全不感知 `wx.*` 的回调地狱、MTU 差异、重连时序？

这一票是纯工程封装：把 `wx.*` 的异步回调包成 Promise，把「扫描 → 连接 → 协商 MTU → 订阅 → 读 State」串成一条固定流水线，把断线重连与退避重试做进去，再叠一层 20Hz 节流。**不含任何 UI**。

### 要实现的

1. **BLE 传输层**
   - Promise 化的 `wx.*` 封装（含超时、错误码归一）
   - 扫描（serviceId 过滤）→ 连接 → MTU 协商（失败降级）→ 订阅 notify → 读 State 的固定序列
   - 断线监听 + 自动重连（1s/2s/4s 退避，有限次数）
   - 缓存 `deviceId`，进前台静默回连
2. **协议 codec**（与固件逐字节对齐）
   - encode：命令 → 字节数组
   - decode：字节数组 → `{ cmd, seq, payload, resultCode }`
   - checksum 与测试向量完全一致
3. **节流层**
   - 20Hz 上限，新值覆盖未发旧值（不排队）
   - 连续量不重传；开关类可重传一次
   - ACK 超时作为「可能断线」信号触发重连检查
4. **协议日志**
   - 每帧记录 `{ ts, dir, hex, parsed }`
   - 环形缓冲（如保留最近 200 帧）
   - 供 UI 层的日志面板消费

### 不做

不做任何页面、WXML、样式。这一票的产物是可被 UI 调用的模块。

## Blocked by

- 【协议规格定稿】
- 【小程序 BLE 探测】——平台差异的事实要先用那一票摸清

## 交付

- `miniprogram/utils/ble/` 下的传输层
- `miniprogram/utils/protocol/` 下的 codec
- vitest 单测：codec 跑通 `protocol-testvectors.json`，节流层用假计时器验证「覆盖而非排队」

## 验收

- [ ] codec 单测全绿，与固件共用同一份测试向量
- [ ] 节流层单测证明：100Hz 输入 → 输出不超过 20Hz，且发的是最新值
- [ ] 传输层在真机上能完成完整初始化序列（可用一个调试页触发）
- [ ] 拔掉设备电源后，重连逻辑按退避节奏重试，不无限循环
- [ ] 所有 `wx.*` 错误码都有中文可读的映射
